# Dependency policy

RelKit tracks pre-release and locally patched dependencies as explicit debt.

- Packages installed into user projects depend only on stable releases, unless a row below lists the
  exception.
- Every pre-release version a workspace package depends on directly, and every patched dependency,
  has a row with an owner and an exit plan.
- Local patches are sent upstream; a patch stays only until the upstream release that contains it.

`bun scripts/dependency-policy.ts` (part of `bun run check`) compares this table with `bun.lock`. It
fails when the lockfile resolves a direct pre-release or a patch that has no row, when a row has no
owner or exit plan, and when a row names a version the lockfile no longer resolves.

## Version updates

Effect, Hono and Better Auth move to the latest patch or minor release in their line when the full
test suite passes. On 2026-11-03 Hono moved from 4.13.7 to 4.13.16.

Pins that cannot move yet:

| Package                  | Pinned | Available | Why it stays                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Owner         |

| `effect` and `@effect/*` | 4.0.1  | 4.1.2     | With 4.1.2, six package tests fail that pass on 4.0.1: error tags in operation logs (`ConnectionError` where `TypeError` was recorded), primary-failure and finalizer-defect retention in `@relkit/better-auth` and `@relkit/testing`, and abort handling of pending pulls in `relkit/engine` invocation metrics. Moving needs those runtime paths adapted to Effect 4.1's cause and interruption behavior. `@effect/docgen` moves with Effect; its patch also needs porting, because the 4.0.1 patch does not apply cleanly to 4.1.2. | @mustafaskyer |
