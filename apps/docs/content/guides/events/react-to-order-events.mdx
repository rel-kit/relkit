Create an order, publish its details, and run a confirmation function. This example logs the reaction without sending email or writing to a database.

<Callout type="note" title="Before you begin" icon="clipboard-check">
  You'll need an [existing RELKIT application](/docs/learn/create-an-app) and Bun 1.3.10 or later.
</Callout>

Create the files shown below. If your app already has the Orders example, update those files instead. Run all commands from your app's root.

### Check and test delivery

Configure a compatible event adapter under singular `event`, then check the graph:

```sh
bun run check
bun run typecheck
```

No environment mode silently substitutes an event provider. For a credential-free behavior test, use
the deterministic event harness:

[Event-harness regression test](https://github.com/rel-kit/relkit/blob/main/packages/testing/tests/compatibility/events.test.ts)

Start the application with `bun run dev`. In a second terminal, create an order:

```sh
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"order-100","sku":"book","quantity":2}'
```

Expect HTTP `201` and `totalCents: 200`. In the application terminal, look for
`order.confirmation.requested` with `orderId=order-100`. The response confirms publication was
accepted; the log separately confirms that the consumer ran.

</Step>
<Step icon="git-branch">

## 3. Add another reaction [#add-another-reaction]

In a second terminal, open your app's root directory and copy the consumer:

```sh
cp src/services/orders/functions/order-confirmation.function.ts src/services/orders/functions/order-analytics.function.ts
```

Change the copy's `id` to `orders.analytics` and its log message to `order.analytics.recorded`. Keep `event: "orders.created"`.

After configuring an event binding and starting the app, call the publishing route with `orderId` set to
`order-101`. Look for both `order.confirmation.requested` and `order.analytics.recorded` with that ID. You
added a reaction without changing the publishing function.

Optionally complete the separate [Inspector setup](/docs/modules/operations/inspector), then open
`orders.created` in its UI at `http://localhost:3210` to see both subscribers under **Consumer functions**.

</Step>
