Move an Orders API from Express or Hono to RelKit without a big-bang rewrite. You will keep the old app serving its endpoints, move `GET /orders/:orderId` and `POST /orders` into RelKit functions and routes, and test both.

<Callout type="note" title="Before you begin" icon="clipboard-check">
  You need Bun **1.3.10 or later** and a RelKit application. Create one with `bunx
  create-relkit@latest my-api --template api`, or follow [Create and run an
  API](/docs/learn/create-an-app). The complete example lives in
  [`apps/docs/examples/migrate`](https://github.com/rel-kit/relkit/tree/main/apps/docs/examples/migrate),
  and its tests run with the documentation test suite.
</Callout>

## How the pieces map

| Express or Hono                                        | RelKit                                                                                             |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `app.get("/orders/:orderId", handler)`                 | `src/routes/orders/[orderId]/route.ts` exporting `GET`                                             |
| The handler body                                       | A function in `src/services/orders/functions` with `input` and `output` schemas                    |
| Validation middleware such as `zod-validator`          | The function's `input` schema; invalid requests get a 422 response                                 |
| `res.status(404).json(...)` or `c.json(..., 404)`      | A declared error with `http: { status: 404 }`                                                      |
| Error-handling middleware                              | Declared errors, returned from the function                                                        |
| `app.use(middleware)` for CORS, headers or rate limits | [HTTP middleware](/docs/modules/http/middleware) and [rate limits](/docs/modules/http/rate-limits) |
| `app.listen(3000)`                                     | `server.port` in `relkit.config.ts`, started with `bun run dev`                                    |
| `supertest` or `app.request()` in tests                | `createTestApplication` from `@relkit/testing`                                                     |

## 1. Keep the old app running [#keep-the-old-app-running]

Start from your existing endpoint:

<Tabs sync={false} hash={false}>
<Tab title="Express" icon="server">

```ts title="server.ts — Express"
import express from "express";

const app = express();

app.get("/orders/:orderId", (req, res) => {
  const { orderId } = req.params;
  if (orderId === "missing")
    return res.status(404).json({ error: `Order ${orderId} was not found` });
  res.json({ orderId, status: "confirmed", totalCents: 1_000 });
});

app.listen(4000);
```

Express handlers take Node.js request and response objects, so RelKit can't mount an Express app directly. Keep it running on its own port and move endpoints one at a time, pointing your proxy or clients at RelKit as each one moves.

</Tab>
<Tab title="Hono" icon="flame">

## 4. Test the moved and remaining endpoints [#test-the-endpoints]

`createTestApplication` runs the whole application in memory, so one test file covers the moved endpoints and the ones still served by the old app:

<include
  source="apps/docs/examples/migrate/tests/orders.route.test.ts"
  lang="ts"

  /_snippets/source/apps/docs/examples/migrate/tests/orders.route.test.ts

In your application, you can leave out `projectRoot` when you run `bun test` from the application root. From the application root, run:

```sh title="Terminal — application root"
bun run check
bun test
```

`bun run check` checks the application graph, including duplicate or ambiguous routes, and reports each problem with a `RELKIT_*` code. The tests pass when the moved endpoints and the `/legacy` endpoints answer as expected.

</Step>
<Step icon="circle-check">

## 5. Finish the move [#finish-the-move]

Repeat steps 2 to 4 for each remaining endpoint. When nothing is left under `/legacy`, delete `src/legacy` and `src/routes/legacy`, and remove `hono` from the application if nothing else uses it. For an Express app, stop the old server once your proxy sends every path to RelKit.

</Step>
