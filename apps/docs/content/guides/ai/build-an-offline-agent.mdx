Add a greeting assistant to your existing RELKIT app. It combines a native LangChain model, native
middleware and tool, and a RELKIT function-backed tool. The small example runs without a database,
network request, or paid model call.

<Callout type="note" title="Before you begin" icon="clipboard-check">
You'll need an existing RELKIT application and Bun 1.3.10 or later. The example uses an offline model; no model API key is required.
</Callout>

Create the files below, or update them if they already exist. Run commands from your app's root.
The minimal app does not include the optional native execution packages. Install `@relkit/langchain`
and its selected SDK peers first; `@relkit/local` supplies the explicit profiles used below.

## Optional: use a production model [#use-a-production-model]

Skip this step if you only want the offline example. Install the LangChain model package for your
provider, construct its compatible chat model in server code, and pass that instance or a lazy factory to
`model`. Provider credentials remain server-only and live calls may cost money. For
[MCP only](/docs/modules/ai/mcp), use the function-backed tool without adding an agent.

Do not put a key in the agent's instructions or commit it to source control. Tests should continue to
inject or declare deterministic native models explicitly; no environment name silently selects a paid
provider.

```sh
bun run check
bun run dev
```

Optionally follow the separate [Inspector installation and bridge setup](/docs/modules/operations/inspector).
After starting that tool independently, open its UI, normally at `http://localhost:3210`. Under **Agents**, select
`hello.assistant` to inspect its tools, middleware state, and execution. To let an external AI client call
the greeting function directly, follow [Tools over MCP](/docs/modules/ai/mcp).
