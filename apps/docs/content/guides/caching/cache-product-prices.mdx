Add a product-price lookup to your application. You'll load a price, reuse it for one minute, and verify that it loads again after expiration. This example uses a fixed price, so it needs no database.

<Callout type="note" title="Before you begin" icon="clipboard-check">
  Continue from the [Orders endpoint](/docs/learn/first-route), so the Orders service already
  exists. Create the two files below, or update them if they already exist. Run commands from your
  app's root. This selected local profile requires a running Docker daemon and uses Redis.
</Callout>

## 4. Expose a price endpoint [#expose-a-price-endpoint]

In `src/services/orders/service.ts`, import the function and add `getPrice` to the existing
`functions` object. Keep the service's other members:

```ts title="src/services/orders/service.ts — new import"
import getPrice from "./functions/get-price.function.js";
```

Create `src/routes/prices/route.ts`:

```ts title="src/routes/prices/route.ts"
import { defineServiceRoutes } from "@relkit/app/routes";
import orders from "@app/services/orders/service.js";

export const { GET } = defineServiceRoutes(orders, {
  GET: { member: "getPrice" },
});
```

</Step>
<Step icon="repeat">

## 5. Try a miss and a hit [#try-a-miss-and-a-hit]

Check and start the app:

```sh
bun run check
```

```sh
bun run dev
```

Docker is contacted only after the checked plan exists. To prove there is no hidden fallback, use
`bun run dev --local=off`; startup then requires the named connected/infrastructure values.

In a second terminal, send the same request twice:

```sh
curl http://localhost:3000/prices\?sku=book-demo
curl http://localhost:3000/prices\?sku=book-demo
```

Expect this output:

```json
{ "sku": "book-demo", "unitPriceCents": 1000 }
```

Look for `price.loaded` with `sku=book-demo` in the app terminal. The second request within one minute returns the same output without another `price.loaded` log. Use a new SKU if this key was already cached from an earlier run.

</Step>
<Step icon="timer">

## 6. Inspect expiration [#inspect-expiration]

Optionally complete [Inspector setup](/docs/modules/operations/inspector). Open **Cache**, select `orders.prices`, and find the key containing `book-demo`. Its remaining TTL is the time before the cached value expires. Click **View value** to see `1000`.

Once the minute has passed, repeat the curl request with the same SKU. A new `price.loaded` log confirms the price was loaded again. The next request performs the reload; nothing refreshes in the background.

Tests must pass an explicit replacement for the `requests` profile; no test environment selects
a fake for you. In your app, replace the fixed price with a database lookup and
[invalidate the cached price after updates](/docs/modules/caching/expiration). Before deploying, review which
profiles are connected and which are infrastructure-owned in [Integrations](/docs/modules/integrations).

</Step>
