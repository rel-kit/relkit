Add `POST /uploads` to an existing application. You'll send two images, store them in the assets bucket, and check the returned object keys.

<Callout type="note" title="Before you begin" icon="clipboard-check">
You'll need a running RELKIT application, Docker for local MinIO, and two PNG images.
</Callout>

Create the four files below. If your app already has an Assets service or an uploads route, merge these members into it. Run commands from your app's root.

## 5. Upload two images [#upload-two-images]

Check and start the app:

```sh
bun run check
```

```sh
bun run dev
```

The local MinIO recipe supplies generated binding-only credentials and loopback ports. Keep the app running
and open a second terminal in the app's root. `bun run dev --local=off` disables recipes and requires the
named connected/infrastructure values instead.

Place two small PNG images named `cover.png` and `detail.png` there. Keep their combined size below 1 MB for this request, then send:

```sh
curl -i http://localhost:3000/uploads \
  -F label=book-photos \
  -F 'primary=@cover.png;type=image/png' \
  -F 'attachments=@detail.png;type=image/png'
```

Use your app's configured port if it differs from `3000`. Expect HTTP 200:

```json
{ "label": "book-photos", "files": ["cover.png", "detail.png"] }
```

</Step>
<Step icon="circle-check">

## 6. Check the stored files [#check-the-stored-files]

Optionally complete the separate [Inspector installation, bridge and tool setup](/docs/modules/operations/inspector).
Open its UI, normally at `http://localhost:3210`. Select **Buckets**, open `assets.objects`, and look
for `cover.png` and `detail.png`. Click **Preview** beside either key to view its image.

Tests must provide explicit replacements for profile `assets`; no environment name installs a file fake.
You can now [read the files or create download links](/docs/modules/storage/read-delete). Before deploying, review
ownership in [Integrations](/docs/modules/integrations) and add authentication to the upload endpoint.

</Step>
