## `outbox.ts`

Transactional outbox for Drizzle. `outbox(tx).publish(event, payload)`
validates the payload against the event contract and writes the envelope
and its per-consumer deliveries with one statement on the caller's Drizzle
transaction, so the event commits or rolls back with the transaction's other
writes. Consumers run later from the Postgres event provider's loops.

## `database.ts`

Owns one Postgres connection pool for a backend namespace. The pool is a
`@effect/sql-pg` Layer held by a ManagedRuntime; acquiring it applies the
idempotent DDL inside a transaction holding an advisory lock, so instances
that start together create the tables once. Background loops are forked into
the same runtime and interrupted before the pool closes.

## `events-provider.ts`

The Postgres event provider. Registering a durable trigger records its
consumer row; `publish` persists the envelope and one delivery per consumer
in a single statement; consumer loops lease due deliveries with
`FOR UPDATE SKIP LOCKED`, invoke the trigger, and complete, retry or
dead-letter each delivery on its own under the trigger's retry policy.
Delivery is at least once: a consumer that crashes after its handler
succeeded is invoked again when its lease expires.

## `integration.ts`

runs job workers, the scheduler and event consumers; `api` only serves
requests, submits jobs and publishes events, leaving the work to separate

## `jobs-controls.ts`

Reads, lists and cancels job runs. Cancellation runs in a transaction that
locks the row, so the first terminal transition wins: a queued run becomes
cancelled at once, a running run records the request and its worker observes
it on the next lease heartbeat, and later requests on a terminal run report
`already-terminal`. Each function is a lazy Effect requiring the SQL client.

### PostgresRunNotFoundError (class)

No run with this ID exists in the operation's service. @experimental

## `jobs-lease.ts`

Lease protocol for job runs. A worker claims the oldest due run with
`FOR UPDATE SKIP LOCKED`, so concurrent workers never claim the same row; a
claim stamps an owner token and an expiry that heartbeats extend. Every
settlement is fenced on the owner token, so a worker whose lease expired and
was re-claimed cannot overwrite the new attempt. Expired leases are claimable
again while attempts remain; exhausted ones end failed and dead-lettered.

## `jobs-worker.ts`

## `schedules-tick.ts`

Enqueues schedule occurrences exactly once across instances. One pass locks
due schedule rows with `FOR UPDATE SKIP LOCKED`, claims each occurrence by
inserting into the occurrences table, whose primary key is (service,
schedule, occurrence time), enqueues the run in the same transaction, and
advances the pending occurrence. A contender that reads a stale pending
occurrence loses on the primary key, so it never enqueues a second run.

### ClaimedOccurrence (interface)

}
