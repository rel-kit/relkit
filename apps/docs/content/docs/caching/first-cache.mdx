description: Add a cached price lookup to an existing app and see hits and expiration in the Inspector.

Add a product-price lookup to your existing RelKit app. You'll load a price, reuse it for one minute, and see it load again after expiration. The example uses a fixed price instead of requiring a database.

Create the two files below, or update them if they already exist. Run commands from your app's root.

## Configure caching

Install `@relkit/redis` and `@relkit/docker`, then import `redis`, `docker`, and `env as binding`
from their standalone packages and `@relkit/app/config`. Add this singular `cache` entry inside
`defineApp()`:

<include cwd lang="ts" meta='title="relkit.config.ts — cache configuration"'>
  ../../examples/commerce/relkit.config.ts#cache-profile
</include>

Profile `requests` is a connected Redis binding with a Docker overlay. Development starts its pinned Redis
recipe and supplies the binding-local URL; release builds resolve `REQUESTS_REDIS_URL` instead. Profile
`timeline` is a second physical Redis/Valkey server owned by AWS in deployment and also has a local recipe.
The two profiles do not share state.

`defaults.cache` chooses `requests` for unqualified descriptors. `orders.prices` selects it explicitly.
`orders.rate-limits` selects `timeline`; the route's `x-customer-email` projection derives a counter key
inside that cache and does not choose the server.

## Try a miss and a hit

Check and start the app:

```sh
bun run check
```

```sh
bun run dev
```

Docker is contacted only after the checked plan exists. To prove there is no hidden fallback, use
`bun run dev --local=off`; startup then requires the named connected/infrastructure values.

Open your Inspector, normally at `http://localhost:3210`. Select **Functions**, open `orders.get-price`, enter `book-demo` in the **sku** field, and click **Invoke locally**.

Expect this output:

```json
{ "sku": "book-demo", "unitPriceCents": 1000 }
```

Look for `price.loaded` with `sku=book-demo` in the app terminal or the Inspector's **Logs** page. Invoke the same function again within one minute: the output stays the same, with no new `price.loaded` log for that call. Use a new SKU if this key was already cached from an earlier run.

## Inspect expiration

Open **Cache**, select `orders.prices`, and find the key containing `book-demo`. The list shows its remaining TTL. Click **View value** to see `1000`; use **Refresh** to update the list as time passes.

Once the minute has passed, invoke `orders.get-price` with the same SKU. A new `price.loaded` log confirms the price was loaded again. Nothing refreshes in the background: the next request does the work.

Tests must pass explicit replacements for both physical profiles; no test environment selects fakes for
you. In your app, replace the fixed price with a database lookup and
[invalidate the cached price after updates](/docs/caching/expiration). Before deploying, review which
profiles are connected and which are infrastructure-owned in [Integrations](/docs/integrations).
