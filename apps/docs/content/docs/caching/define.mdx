## Scaffold a cache

From the application root, with an existing `orders` service:

```sh
bun run relkit add cache Prices --service orders --provider redis --source docker
```

Creates `src/orders/cache/prices.cache.ts` and configures Docker Redis. Without provider flags,
a default/unique compatible cache profile is reused; otherwise Docker Redis is the fallback.

Choose one configuration form:

| Selection                                  | Command options                               |
| ------------------------------------------ | --------------------------------------------- |
| Existing profile                           | `--profile requests`                          |
| Docker Redis                               | `--provider redis --source docker`            |
| Connected Redis                            | `--provider redis --source connected`         |
| Redis on an existing AWS/Pulumi deployment | `--provider redis --source aws`               |
| Connected Cloudflare KV                    | `--provider cloudflare-kv --source connected` |

Do not combine `--profile` with `--provider` or `--source`. AWS requires an already configured
AWS/Pulumi deployment; scaffolding does not provision it. Connected profiles add named environment
references and blank examples, not credentials. Docker startup is a separate
[post-add confirmation](/docs/start/add-artifacts#start-local-resources).
Declare the cache as a function dependency before using it.

## Define the cache

Use `defineCache` in your app's domain directory. Create `src/orders/cache/prices.cache.ts`:

<include cwd lang="ts" meta='title="src/orders/cache/prices.cache.ts"'>
  ../../examples/commerce/src/orders/cache/prices.cache.ts
</include>

- `id` is the cache's stable, unique name.
- `key` describes how to identify a value. Here, `{ sku: "book" }` identifies one product's price.
- `value` describes what to store: a non-negative integer price in cents.
- `defaultTtlMs` is the lifetime in milliseconds when a write does not specify one. `60_000` means one minute.
- `maxTtlMs` is the longest allowed lifetime. Requests above this limit are rejected, not shortened.
- `profile` selects a physical cache configuration in `relkit.config.ts`. This example uses `"requests"`.

Both lifetime settings are optional. Set a default when data should expire; setting only `maxTtlMs` does not choose a lifetime for every write.

## Check your cache

Make sure your app has a `requests` cache profile. The [tutorial's configuration step](/docs/caching/first-cache#configure-caching) shows how to add one.

From your app's root, run:

```sh
bun run check
```
