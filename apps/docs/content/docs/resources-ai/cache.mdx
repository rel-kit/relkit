A cache stores replaceable values that can be recomputed or safely lost. It is not the source of truth for
orders, payments, or workflow state. RELKIT validates keys and values at the client boundary so local memory
and Redis-compatible providers observe the same application contract.

## Verify cache behavior

<Steps>
  <Step>
    ### Declare the function dependency

    Add the cache descriptor under `dependencies.cache`; use the resulting typed context client rather than a
    global Redis instance.

  </Step>
  <Step>
    ### Test miss, hit, and expiry

    Use the deterministic fake and clock. Count computations to prove the first request misses and the second
    hits, advance beyond the TTL, then prove the value is recomputed. Avoid wall-clock sleeps.

  </Step>
  <Step>
    ### Test invalid values

    Attempt to write a key or value outside its schema and assert the bounded failure. This catches serialization
    drift before a remote provider stores unusable data.

  </Step>
  <Step>
    ### Bind shared production state

    Add a Redis-compatible adapter under `caches`, provide its URL through `env.secret()` when it contains
    credentials, and run `check`. Use a shared cache for counters or rate limits across replicas.

  </Step>
</Steps>

## Counters and rate limits

Numeric cache values support atomic counter operations used by distributed rate limiting. The provider must
implement the required atomicity; a read-then-write sequence in application code is not equivalent under
concurrency.

## Failure strategy

Decide whether a cache outage should fail the request or fall back to the source of truth. Falling back can
overload the underlying system during a broad cache incident, while failing closed can reduce availability.
Make the choice per use case, bound retries, and observe hit rate, latency, and error rate.

<Callout title="Cache only replaceable data">
  If losing a value changes the truth of the business process, use a durable data model or provider
  designed for that state instead of a cache.
</Callout>
