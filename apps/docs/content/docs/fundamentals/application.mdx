---
title: Application, providers, and configuration
description: Define the application once and select logical provider profiles by environment.
---

`src/app.ts` exports one `defineApp` descriptor. Providers are logical profiles; functions depend on
declared resources rather than concrete SDK clients. AI model providers use the same value-free
configuration boundary and are constructed only after the active environment resolves.

```ts
import { awsProviders, defineApp, localProviders, testProviders } from "@zsys/app";

export default defineApp({
  id: "commerce-api",
  env,
  providers: {
    development: localProviders({ stateDirectory: ".zsys/state" }),
    test: testProviders({ deterministicIds: true, deterministicClock: true }),
    production: awsProviders({
      region: env.AWS_REGION,
      modelProviders: {
        defaultProvider: "openai",
        defaultModel: "gpt-5-mini",
        openai: { apiKey: env.OPENAI_API_KEY },
        anthropic: {
          defaultModel: "claude-sonnet-4-5",
          apiKey: env.ANTHROPIC_API_KEY,
        },
      },
    }),
  },
});
```

`defaultProvider` and `defaultModel` are both required when `modelProviders` is present. Provider
credentials should be `env` references, never live SDK clients or secrets embedded in descriptors.
Agents may omit `model`, select a provider default by name, or select an exact `provider:model`.

Use `defineEnv` for value-free environment contracts. Mark secrets as sensitive and list the profiles
where each value is required. `PORT` is framework-reserved and must not appear in the application
environment definition. `zsys env list`, `check`, `explain`, and `example` expose metadata without
printing secret values.

Public configuration only controls server and inspector behavior. `entry`, `source`, `exclude`, and
`generatedDirectory` are removed; using them produces migration diagnostics rather than being ignored.
