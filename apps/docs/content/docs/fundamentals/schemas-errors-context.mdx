---
title: Schemas, errors, and context
description: Validate runtime boundaries, declare failures, and propagate invocation metadata safely.
---

`@relkit/schema` implements Standard Schema v1. Compose `z.object`, strings, numbers, literals, arrays,
optional/default values, unions, and refinements, then use `validate` or let a RELKIT boundary validate
automatically.

Declared errors are data contracts:

```ts
const orderNotFound = defineError({
  data: z.object({ orderId: z.string() }),
  http: { status: 404 },
  retry: { kind: "later", afterMs: 1_000 },
});
```

Throw or return errors through the owning function APIs; do not turn arbitrary exceptions into public
responses. HTTP status metadata contributes an inferred OpenAPI response. Input validation contributes
`422` automatically. Error IDs may be inferred from a named source binding. Omit `retry` for a terminal
application failure; `"later"` or `{ kind: "later", afterMs }` marks a retryable failure and `afterMs`
is only a minimum delay hint for jobs and durable event deliveries. HTTP and direct calls do not retry
the function automatically.

Invocation context carries the abort signal, deadline, trace/correlation/causation identifiers, source,
declared managed-resource clients, and an immutable service-scoped context when service middleware is
active. Treat it as invocation-scoped and never store it globally. HTTP transport data remains separate
on the optional request view.
