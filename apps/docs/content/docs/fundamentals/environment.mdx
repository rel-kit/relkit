title: Environment contracts
description: Parse runtime values once, mark secrets for redaction, and fail before handlers run when configuration is invalid.

Environment variables enter a RELKIT application through one typed contract rather than scattered `process.env`
reads. Every process value starts as text; the contract parses it, applies intentional defaults, identifies
secrets, and controls the values available through `context.env`.

## Define application values

<include cwd lang="ts" meta='title="templates/default/v1/api/src/platform/env.ts"'>
  ../../templates/default/v1/api/src/platform/env.ts
</include>

Builders such as `env.string()`, `env.url()`, `env.boolean()`, numeric variants, and `env.literal(...)` define
the accepted runtime value. Defaults are useful for harmless local policy such as log level. Credentials and
other required production values should fail clearly when absent instead of receiving placeholder defaults.

`env.secret()` marks a value as sensitive so generated output, diagnostics, telemetry, and Inspector payloads
can redact it. Secret marking is a safety boundary, not permission to log the value.

## Separate environment from binding references

The contract passed as `defineApp({ env })` resolves values available to application handlers. Integration
configuration also uses named binding references such as `binding.string(...)` and `binding.secret(...)`.
Those references describe runtime wiring for an adapter; they are not additional `context.env` fields unless
the application environment contract declares them too.

Use source-controlled configuration for stable topology and policy. Use environment values for machine-, stack-,
or secret-specific data. Never place resolved credentials in source, graphs, manifests, deployment plans, or
test snapshots.

## Inspect configuration safely

```sh title="Terminal — relkit-orders"
bun run relkit env check
bun run relkit env list
bun run relkit env explain LOG_LEVEL
bun run relkit env example
```

`check` validates the active values, `list` reports value status without printing secret contents, `explain`
describes one declaration, and `example` renders a safe template. Run `bun run check` after changing the contract
so generated types and graph metadata stay current.

<Callout type="warn" title="RELKIT_ENV is reserved">
  Select a provider environment with the CLI's `--environment` option. Do not declare or branch
  application behavior on a custom `RELKIT_ENV` field.
</Callout>
