---
title: Domain-first migration
description: Move a layer-first RELKIT application to domain services, service routes, Drizzle, and Better Auth.
---

This release intentionally removes the layer-first layout and the old service,
data-model, and auth adapter APIs. Migrate the application as one change.

<Steps>
  <Step>
    ### Move files into owner domains

    Establish every domain directory and its single `service.ts` before changing
    route imports.

  </Step>
  <Step>
    ### Replace removed authoring APIs

    Convert service members, Drizzle models, and Better Auth configuration to
    their new factories.

  </Step>
  <Step>
    ### Compile and verify boundaries

    Run `bun run check`, type checking, and focused tests until every diagnostic
    points only at intentional migration fixtures.

  </Step>
</Steps>

## Move files by owner

```text
src/functions/orders/*  -> src/orders/functions/*
src/events/orders/*     -> src/orders/events/*
src/services/orders.ts  -> src/orders/service.ts
src/middleware/*        -> src/routes/middleware/*
src/transforms/*        -> src/routes/transforms/*
src/env.ts              -> src/platform/env.ts
```

Create exactly one `service.ts` per domain. Export public functions and events
as direct members with `defineService`; leave internal artifacts out of the
service. Replace cross-domain internal imports with imports of the owning
domain's service.

## Replace removed service behavior

- Replace `service.functions.createOrder` with `service.createOrder`.
- Move service middleware to route middleware or explicit function logic.
- Replace `context.service` values with typed function dependencies or route
  middleware context.
- Do not add `imports`; use ordinary TypeScript service imports.

Use `defineServiceRoutes(service, methods)` when one route file maps methods to
public service functions. Keep `defineRoute` for individual functions and raw
handlers.

## Replace database and auth adapters

- Replace `defineDataModel` with one `src/database/service.ts` using
  `defineDrizzleService({ schema, client, models, dispose })`.
- Replace custom model classes with `defineModel({ table, extend })`.
- Replace `betterAuthAdapter` with one `src/auth/service.ts` using
  `defineBetterAuthService` and native Better Auth options.
- Mount `auth.handler` on one catch-all `ALL` route. RELKIT derives `basePath`
  and resolves the sole Drizzle service automatically.

The compiler reports legacy roots, missing or duplicate services, orphan
descriptors, invalid domain IDs, and cross-domain boundary imports with source
locations. There are no compatibility aliases or automatic migrations.

For the current workflow, use [Database](/docs/database) for service setup,
[custom models](/docs/database/models) for extensions, and
[database migrations](/docs/database/migrations) for applying schema changes safely.

Run `bun run check` after each domain move, then run type checking and focused
tests once all route imports point at services. Commit generated graph and
manifest updates only after diagnostics are clean, so review diffs describe the
new domain ownership instead of an intermediate mixed layout.

```sh title="Terminal"
bun run check
bun run typecheck
```
