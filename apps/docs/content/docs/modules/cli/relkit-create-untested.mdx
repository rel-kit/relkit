`create-relkit` and `relkit create` print this warning when CI has not measured your combination of template and options on your RelKit version and Bun version. The project is still created.

```txt title="Terminal"
RELKIT_CREATE_UNTESTED: template=agent/jobs=none/cloud=none/deploy=none/examples=on has not been tested with RelKit 0.8.8 on Bun 1.4. Creation continues; pass --strict to refuse untested combinations. See https://relkit.dev/docs/modules/cli/relkit-create-untested
```

## Why it happens

Before each release, CI creates every template, starts it and checks that it responds. The creator compares your choice with those results using the RelKit release, the template, and the Bun major and minor version. Bun patch releases count as tested, so Bun 1.3.11 matches results from Bun 1.3.10.

You see the warning when:

- your Bun minor version is newer than the one CI tested, such as Bun 1.4 when CI tested 1.3;
- you chose a template or option combination that CI did not measure or that failed its last measurement.

## What to do

1. Continue with the project. Run `bun run check` and `bun run dev`; most untested combinations work.
2. If something fails, switch to the Bun version named in the generated `package.json` `packageManager` field, which is the version CI tested.
3. Report the failure on the RelKit issue tracker with the warning line, so the combination can be fixed and measured.

## Refuse untested combinations

Pass `--strict` when a script or CI job must only create tested projects. Strict creation stops before writing any file, exits with status 2 and lists the tested combinations:

```sh title="Terminal — parent directory"
bunx create-relkit@latest my-app --template agent --strict
```

See [Creation options](/docs/modules/cli/create-an-app#untested-combinations) for the available templates.
