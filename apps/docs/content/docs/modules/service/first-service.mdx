Trace the Orders endpoint through its route, service, and pricing function to see where each responsibility belongs. You will identify which file owns pricing, which operations the Orders service exposes, and
how a route reaches them. That chapter adds these maintained API-candidate sources to the certified
minimal starter; it does not require an uncertified creation tuple. Run commands from the app root.

<Callout type="note" title="Before you begin" icon="clipboard-check">
  Continue from the [Orders endpoint](/docs/learn/first-route), which supplies the function used
  below.
</Callout>

The endpoint chapter uses `relkit add function --create-service` to create the service and its
first operation together. To start a different domain, use
[`relkit add service`](/docs/modules/service/define#scaffold-a-service); to extend this one, use
[`relkit add function --service orders`](/docs/learn/concepts/functions#scaffold-a-callable-function).
Keep the existing Orders files while following this walkthrough.

## Verify the boundary

From `relkit-orders`, run:

Create `tests/integration/orders.route.test.ts` from the [HTTP route test](/docs/modules/http/first-route)
before running its command below. These tests are Orders extensions, not files shipped by minimal.

```sh
bun run check
bun run typecheck
bun test tests/unit/orders.function.test.ts
bun test tests/integration/orders.route.test.ts
```

Expect all four commands to succeed after adding the Orders sources and tests. The unit test checks the reusable
operation; the HTTP test checks the public route's status and body. Continue with
[the endpoint chapter](/docs/learn/first-route) to change pricing and verify the result.
