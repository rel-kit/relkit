A cache temporarily stores a value so later requests can reuse it without repeating the original work. Product prices, search results, and calculated summaries are common examples. Keep the original data in your database or another source you can read again.

Use caching when a lookup is expensive and a slightly older result is acceptable. Skip it when every request must see the latest value.

## The Caching API

Usually, caching means connecting a Redis client, choosing keys, serializing values, and checking for missing entries. With RELKIT, define the key and value shapes, give your function access, and use `getOrSet()` to load missing values.

| API                                          | What you use it for                                    |
| -------------------------------------------- | ------------------------------------------------------ |
| [`defineCache`](/docs/api/cache#definecache) | Define the cache's keys, values, and expiration time.  |
| `dependencies.cache`                         | Give a function access to a cache.                     |
| `context.cache.prices.getOrSet(key, load)`   | Reuse a saved value or load and save it when missing.  |
| `context.cache.prices.set(key, value)`       | Save or replace a value.                               |
| `context.cache.prices.delete(key)`           | Remove a value so the next lookup can load fresh data. |

You can use caches in event functions too, and in ordinary functions called by jobs and tools.

## Try it in your app

Follow the [cached-price example](/guides/caching/cache-product-prices) for the first working cache. It runs
with Docker Redis and no cloud credentials. Use [Define a cache](/docs/modules/caching/define) when you need
to choose keys, values, and expiration for your own data.

After the separate [Inspector setup](/docs/modules/operations/inspector), open **Cache** and select your cache
to see keys and their remaining lifetime. Choose **View value** to inspect a saved value.
