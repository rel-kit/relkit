Define a route to connect an HTTP method and path to a public service operation. Import the target through its domain's
`service.ts`; never reach into another domain's private function directory from a route.
The [file-system conventions](/docs/modules/http/routes) determine the URL and allowed method exports.

## Scaffold a route

Run these commands from an installed application's root. Choose the mode that matches the
endpoint you are creating; then edit the generated file using the API examples below.

<Tabs sync={false} hash={false}>
<Tab title="Service function" icon="route">

To route through existing public functions, use service-route mode. With `details` and
`updateDetails` public callable members in the `users` service:

```sh
bun run relkit add route /users/:id/details \
  --mode service-route --service users \
  --map GET=details --map PATCH=updateDetails
```

This creates `src/routes/users/[id]/details/route.ts` with `defineServiceRoutes`. The
mapped names are public service member names, not private filenames or event IDs. Headless
service-route commands need at least one `--map`; supported methods are `GET`, `POST`,
`PUT`, `PATCH`, `DELETE`, `HEAD`, and `OPTIONS`. `ALL` is auth-only.

</Tab>
<Tab title="Raw handler" icon="code-xml">

From an installed application's root, create a standalone raw handler:

```sh
bun run relkit add route /status --mode route
```

This creates `src/routes/status/route.ts` with a raw `GET` returning `{ ok: true }`.
It needs no service or function. It appears in OpenAPI/Scalar with a generic response contract,
not an inferred function response schema. `--map` is not accepted in this mode.

</Tab>
</Tabs>

For a complete function-backed endpoint, follow [Add an Orders endpoint](/docs/learn/first-route).
The CLI creates the method mapping; add request mapping, response status, and policy in source.

| URL passed to the command | Generated file                           |
| ------------------------- | ---------------------------------------- |
| `/`                       | `src/routes/route.ts`                    |
| `/users/:id/details`      | `src/routes/users/[id]/details/route.ts` |
| `/files/*parts`           | `src/routes/files/[...parts]/route.ts`   |
| `/files/*parts?`          | `src/routes/files/[[...parts]]/route.ts` |

Write route paths without quotes. Escape literal shell wildcards, for example `/files/\*parts`
or `/files/\*parts\?`, so the shell passes them to the CLI unchanged. Existing target files are never
overwritten; edit an existing route to add another method. Run `bun run check`, then verify
the endpoint and its entry in `/_relkit/v1/openapi.json` while dev is running. The
[Scalar UI](/docs/modules/http/openapi) is available when explicitly selected.

For every route scaffolding flag, see the [route command reference](/docs/api/cli#relkit-add-route-path).

This is `POST /echo`. Omit `request` and `responses` when the input schema and output describe ordinary
JSON correctly. The descriptor selects behavior; it does not call `echo.echo.invoke()` at module load.

A target must be an ordinary callable function exposed by a service. An event contract, event-only
subscriber, tool, or agent is not a route target. To expose agent behavior, use a public
[function that calls the agent](/docs/modules/service/organization#tools-and-agents-stay-with-their-business-domain).

Keep the exported destructuring form. Supported keys are `GET`, `POST`, `PUT`, `PATCH`, `DELETE`,
`HEAD`, and `OPTIONS`; do not rename the bindings, add a rest binding, or use a default export.
`ALL` is reserved for [raw handlers](/docs/modules/http/raw-handlers), not `defineServiceRoutes`.

Several route files can use the same service. Individual `defineRoute` exports in one file can target
different public services. Put reusable cross-domain orchestration in a domain function instead of
creating business logic inside the route module.

## Add only the transport options you need

| Option                               | Use it when…                                                                                                                                       |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `request`                            | Inference cannot express headers, cookies, names, or nesting. It replaces all inferred input mapping. See [requests](/docs/modules/http/requests). |
| `accept`                             | The route consumes `multipart/form-data` instead of JSON. See [uploads](/docs/modules/http/uploads).                                               |
| `successStatus`                      | One successful JSON operation needs a different `2xx` status, such as `201`.                                                                       |
| `responses`                          | You need a complete explicit response contract. It replaces inference; see [responses](/docs/modules/http/responses).                              |
| `maxBodyBytes`                       | Parsing this route needs a specific positive byte ceiling.                                                                                         |
| `timeoutMs`                          | The function invocation needs a route-specific positive timeout.                                                                                   |
| `rateLimit`                          | Requests need a keyed limit before mapping and invocation. See [rate limits](/docs/modules/http/rate-limits).                                      |
| `id`, `title`, `description`, `tags` | You need stable operation identity or human-facing metadata.                                                                                       |

Do not add `path` or `method`: the compiler derives both from source. There is no service-level URL
prefix or middleware property. The `auth` option is specific to a recognized Better Auth raw handler,
not a generic authorization flag for a function route.

## Check the new operation

From the application root:

```sh
bun run check
bun run typecheck
```

Resolve diagnostics before starting the server. Check the generated route method, path, target,
input mapping, and responses. Then test the endpoint itself: a direct function test does not exercise
HTTP parsing or policy. The [first-route walkthrough](/docs/modules/http/first-route) includes both the source
and an in-process HTTP test.
