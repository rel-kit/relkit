## Bootstrap identity

`GET /_relkit/v1/client/identity` is private and non-cacheable. It returns opaque identity scope,
session epoch, application ID, and public fingerprint. Scope or epoch changes abort in-flight work,
clear private RELKIT stores, grants, and presence, and reject late callbacks.

## Connect a provider

Use `BetterAuthRelkitClientProvider` from `@relkit/better-auth/react` for cookie sessions. A manual
`identityKey` adds a tenant/application partition but never grants authority. Cross-origin cookies
still require exact credentialed CORS, suitable cookie `SameSite` policy, CSRF protection, and an
allowed Origin.

Wrap the part of your app that calls RELKIT hooks in `AuthProvider`. For a same-origin proxy,
forward the backend's `/api/auth` mount as well as `/rpc` and `/_relkit`, and configure Better Auth's
trusted origins for the frontend. Do not nest a second generic provider around private queries.
The wrapper responds to native session changes; it does not replace the server's authorization.

Reference: [`BetterAuthRelkitClientProvider`](/docs/api/better-auth#betterauthrelkitclientprovider).
