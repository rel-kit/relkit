Use a mutation for a request that changes application state, and track whether the server accepted it.

<Callout type="note" title="Before you begin" icon="clipboard-check">
Complete [frontend installation and contract pull](/docs/modules/client) before using this guide.
Keep its selected React/query peers and generated declarations in the frontend package.
</Callout>

## Submit once

`useRouteMutation` never runs on mount and defaults to no retry. Known-offline work fails as
`not-sent`; after a request is handed to `fetch`, timeout or disconnect is conservatively `unknown`.
RELKIT stores only scoped reconciliation metadata in `sessionStorage`, never variables or retry
payloads. Application mutations need an application-owned status endpoint to reconcile an unknown
outcome.

Every managed write carries the rendered identity scope and session epoch as a precondition. The
server authenticates independently and compares them before application code runs.
