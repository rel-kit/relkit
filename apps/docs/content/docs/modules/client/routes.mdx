## Query finite routes

`useRoute`, `useInfiniteRoute`, `useSuspenseRoute`, and `useRouteUtils` take a route from the
generated `api` object. They accept only finite exposed routes. Inputs, outputs, errors, selection,
page parameters, signals, and query options are inferred from generated declarations.

The minimal starter's Hello route targets the function `hello.greet`, so its `api` property is
`api.hello.greet`. Import `api` from `@relkit/client` and the hooks from `@relkit/client/react`, then
render this component under the provider from the [Frontend guide](/guides/frontend/connect-react):

## Name routes

A route's `api` path is its target function ID with each part in camelCase. The first part is the
service: `orders.search-orders` becomes `api.orders.searchOrders`.

When several routes target one function, the first one keeps the name. Routes are ordered by
method (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`) and then by path. The others
add their method, such as `api.orders.getOrderHead`. When the method repeats, they add their static
path segments without a leading service name instead: `GET /orders/search` becomes
`api.orders.searchOrdersSearch`.

## Handle errors

A route's error is a union keyed by `code`. Each error the route declares has its own `code`,
`status`, and `data`. Anything else has a `code` from a fixed list, such as `NOT_FOUND`,
`UNAUTHORIZED`, or `INTERNAL_SERVER_ERROR`, or `NETWORK_ERROR` when no response arrived. Check `code`
to narrow `status` and `data`. In the commerce example, `api.orders.getOrder` declares
`orders.not-found` with status 404 and `{ orderId }` data:

```tsx title="src/Order.tsx — component body"
const order = useRoute(api.orders.getOrder, { input: { orderId } });

if (order.error?.code === "orders.not-found") {
  return <p role="alert">No order {order.error.data.orderId}.</p>;
}
if (order.error) return <p role="alert">{order.error.message}</p>;
```

Narrow on `code` rather than `instanceof ORPCError`. The union names every code the route can fail
with, and TypeScript checks each comparison.

## Choose query helpers

| API                                                              | Use it when                                                                                                                                         |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`useRoute`](/docs/api/client#useroute)                          | The component renders loading, error, and success states.                                                                                           |
| [`useSuspenseRoute`](/docs/api/client#usesuspenseroute)          | A ready provider and your Suspense/error boundaries own loading and failure. It throws while the provider is not ready.                             |
| [`useInfiniteRoute`](/docs/api/client#useinfiniteroute)          | The backend already accepts pagination input; supply `initialPageParam`, `input(page)`, and `getNextPageParam`. It does not add backend pagination. |
| [`useRouteUtils`](/docs/api/client#userouteutils)                | You need the selected procedure's underlying query/mutation option builders.                                                                        |
| [`createTanstackQueryUtils`](/docs/api/client#all-exported-apis) | An application outside the RelKit React hooks owns its QueryClient and identity lifecycle. Import it from `@relkit/client/tanstack-query`.          |

The React installation already includes these peers. Its managed hooks use identity-scoped
[`relkitKey`](/docs/api/client#relkitkey) keys. The underlying option builders do not automatically

provider scope when interacting with its cache. See [server rendering](/docs/modules/client/ssr)

## Keep streams separate

These hooks do not accept routes with streaming output. Pass those to `useStream` instead.
Routes marked `client: false` have neither a route-ID RPC procedure nor a URL alias.
