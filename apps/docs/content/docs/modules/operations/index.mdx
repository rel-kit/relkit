During development, run the narrowest check that proves the change. Before releasing an application, run the
complete local sequence:

```sh title="Terminal — relkit-orders"
bun run check
bun run typecheck
bun run test
bun run build
bun run start
```

Building and starting do not create cloud resources. Deployment is a separate, explicit lifecycle.

## Match the repository gate before pushing

RELKIT contributors can run the same locally reproducible CI coverage before a push:

```sh title="Terminal — relkit repository"
bun run prepush
```

That focused merge gate needs no Docker daemon. Use `bun run prepush:full` with Docker available for
full local acceptance, including container/local-service and browser checks. Dependency review is hosted
CI-only. Real AWS acceptance is separately opt-in locally and is not run by CI; it needs explicit
credentials and authorization for cloud cost.
