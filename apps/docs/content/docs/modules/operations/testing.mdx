Choose the test boundary that proves the behavior: a function, an application, or a running HTTP server. Function tests exercise one descriptor without a server.
Application tests load checked configuration and call an in-process HTTP client. Neither layer needs remote
credentials when provider-backed capabilities receive explicit fakes. Use a running backend for final
HTTP middleware, origin, cookie, and transport behavior.

## Install the selected test tooling

The minimal starter already has development-only `@relkit/testing`. In another existing app, install
it explicitly before copying these tests:

<include>/_snippets/generated/installations/testing.mdx</include>

The generic harness installs no optional database, authentication or model SDK. Keep feature adapters
and native SDKs in the application's selected runtime dependencies. Use `@relkit/testing/drizzle`
for database tests, `@relkit/testing/better-auth` for database-backed auth, and native agent helpers
from `@relkit/langchain` or `@relkit/langchain/testing` after [agent setup](/guides/ai/build-an-offline-agent).

The harness runs in process and exposes `application.http`. It maps invalid function input to a
validation `422`, but it does not implement the entire production HTTP pipeline. It does not prove
all middleware, rate limits, OpenAPI behavior, or RPC transport. Close it in `afterAll` so runtime
state and handles do not leak into another test, then send representative requests to the running
backend as the Start journey does.

## Replace provider profiles explicitly

The commerce suite shows the complete shape for cache, bucket, realtime, and agent-state profiles alongside
native model execution:

[Complete commerce HTTP test](https://github.com/rel-kit/relkit/blob/main/examples/commerce/tests/http.test.ts)

Every graph-required capability and profile must have a replacement. `RELKIT_ENV=test` does not silently select
fakes. Use `createTestCacheFake` and `createTestBucketFake` for deterministic resource behavior, and dedicated
test event, job, or agent utilities for those contracts.

## Run the application gate

```sh title="Terminal — relkit-orders"
bun run test
bun run check
bun run typecheck
bun run build
```

Keep live integration and cloud tests separate and opt-in. In the RELKIT repository, `bun run prepush`
runs the focused merge-blocking checks without Docker; `bun run prepush:full` includes Docker acceptance.

Task-first jobs add focused unit, type, contract, restart, client, Inspector, Docker, and provider suites.
The Docker/provider commands are explicit gates; managed cloud acceptance remains separately authorized.
