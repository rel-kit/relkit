RelKit runs your production server on Bun or on Node LTS. You keep developing with Bun; when you
build, you choose the runtime the server and its container image run on.

## Runtime tiers

| Tier   | Runtimes                                     | What is supported                                                                                   |
| ------ | -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Tier 1 | Bun `>=1.3.10`, Node 22 (`>=22.13.0`) and 24 | The production server: HTTP, WebSockets and static files, with the Redis, Sentry and SQLite clients |
| Tier 2 | Cloudflare Workers                           | Planned: HTTP with external durable backends. Not available yet                                     |
| Labs   | Anything else                                | Not tested. It may work, but no test covers it                                                      |

Each package's `engines` field lists the runtimes it supports. These still need Bun on your
machine or in CI:

- the `relkit` CLI (`relkit dev`, `relkit check`, `relkit build`) and `create-relkit`;
- `@relkit/testing`'s in-process test application, which `bun test` runs;
- `@relkit/aws`, whose Valkey cache client uses Bun's Redis client.

## Pre-setup

Start with an app you can already build, such as the [`api` template](/docs/learn/create-an-app),
and install Node 22.13 or later, or Node 24. Check the version:

```sh title="Terminal"
node --version
```

## Build and run on Node

<Steps>
<Step title="Build the server for Node" icon="package">

```sh title="Terminal — application root"
bun run check
bun run relkit build --runtime node
```

The server in `.relkit/build/server/index.js` now listens through Node's HTTP server, and
`.relkit/build/manifest.json` records `"runtime": "node"`. Without `--runtime`, `relkit build`
builds for Bun.

</Step>
<Step title="Start it with Node" icon="play">

```sh title="Terminal — application root"
NODE_ENV=production PORT=3000 node .relkit/build/server/index.js
```

Node reads no `.env` files, so export the variables your app needs before you start it. Open
`http://127.0.0.1:3000/_relkit/v1/health/ready` and expect `"status":"ready"`.

</Step>
<Step title="Run your HTTP tests against the running server" icon="clipboard-check">

In a second terminal, point your route tests at the server:

```sh title="Terminal — application root"
RELKIT_TEST_SERVER_URL=http://127.0.0.1:3000 bun test tests/integration
```

With `RELKIT_TEST_SERVER_URL` set, `createTestApplication` sends `testApp.http` requests to that
server instead of starting the app in the test process. Requests without an `Origin` header get the
server's own, as a browser on your app would send. Members that need the in-process app, such as
`testApp.fakes`, throw in this mode, so run unit tests without it.

</Step>
</Steps>

## Build a Node container image

```sh title="Terminal — application root"
bun run relkit build --runtime node
docker build -t my-app:node .relkit/build
docker run --rm -p 127.0.0.1:3000:3000 my-app:node
```

The Dockerfile has two stages: the pinned Bun image installs the production dependencies, and the
pinned `node:24` image runs `node server/index.js` as the `node` user. Bun does the install
because it applies the dependency patches RelKit selects, which npm does not support.

## Integrations on Node

- **Redis** (`@relkit/redis`) uses `ioredis` on Node and Bun's built-in client on Bun. Both connect
  once, never retry a failed command and keep no offline queue.
- **Sentry** (`@relkit/sentry`) loads `@sentry/node` on Node and `@sentry/bun` on Bun. Install
  both; `relkit add sentry` does.
- **SQLite** with Drizzle: open the database with `openSqliteDatabase` from
  `@relkit/drizzle/sqlite`. It uses `node:sqlite` on Node and `bun:sqlite` on Bun:

```ts title="src/services/database/service.ts"
import { defineDrizzleService } from "@relkit/drizzle";
import { openSqliteDatabase } from "@relkit/drizzle/sqlite";
import * as schema from "./schema/index.js";

export default defineDrizzleService({
  schema,
  client: ({ env }) => openSqliteDatabase(env.DATABASE_PATH ?? ".relkit/state/app.db"),
  dispose: (database) => database.$client.close(),
});
```

Node 22 and 24 print an `ExperimentalWarning` the first time `node:sqlite` loads. `relkit add
database --dialect sqlite` still writes a `bun:sqlite` service; switch it to `openSqliteDatabase`
before you build for Node.

## Limits on Node

- Node's HTTP server sets no request body limit of its own. RelKit's `server.maxBodyBytes` setting
  still rejects larger bodies with `413`.
- `relkit dev` and `relkit start` run your app on Bun.
