A graph describes a workflow whose steps and branching rules belong to your application. RELKIT registers the declared topology and compiles a native LangGraph while preserving native reducers,
parallel scheduling, conditional edges, loops, `Send`, subgraphs, retry behavior, and pending writes.

Agent graph state and checkpoint resources remain the authority for graph continuation. A task may invoke an
agent, but task retries do not silently replace the graph's thread or checkpoint identity; use the existing
agent continuation contract.

`StateSchema` owns native state and reducer behavior. A `defineGraphNode` input schema projects the fields
that node can read; its output validates an object partial update. Declare every possible `Command`
destination in `ends`. The edge builder accepts only registered node IDs plus valid `START` and `END`
sentinels, so stale destinations fail type checking and compilation.

`interrupt()` is graph control flow, not a normal function failure. The review node declares
`resume: z.boolean()`, then returns a native `Command` that applies the validated reply and routes to
`finish`. A resumed node starts again according to LangGraph semantics. Put the interrupt before an
irreversible effect, or make that effect idempotent with a durable business key or application-owned
transaction.

`defineCheckpointerDb` accepts a native `BaseCheckpointSaver`; `defineMemoryDb` accepts a native
`BaseStore`. The tested driver cohort is:

| Resource     | Supported native implementations                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------- |
| Checkpointer | `MemorySaver`, SQLite, PostgreSQL, MongoDB, Redis and shallow Redis, or a compatible custom saver |
| Memory store | `InMemoryStore`, PostgreSQL, MongoDB, or a compatible custom store                                |

The tested `RedisStore` does not satisfy the selected LangGraph `BaseStore` declarations: it lacks
the lifecycle methods and operation-specific batch result typing required by `defineMemoryDb`.
Strict Redis memory-store compatibility is therefore not guaranteed in this cohort. This declaration
limitation does not establish that Redis memory cannot run through LangGraph's internal batching
wrapper. The Redis and shallow Redis checkpointer entries above remain supported separately.

Driver-specific retention, TTL, serialization, shallow-history, and semantic-search capabilities remain
native. RELKIT does not flatten them into options that every driver supposedly supports.

The in-memory saver/store in the example are supplied by the selected LangGraph SDK. External driver
packages are application-owned dependencies. Install only the driver you choose, in the backend root;
these pins come from the native integration's tested driver declarations:

driver deployment. Keep the Redis memory-store limitation above when choosing a driver.

## Initialize and own resources explicitly

RELKIT never calls driver `.setup()`, runs migrations, creates tables or indexes, installs extensions, or
pushes an application schema during compilation, inspection, activation, or an ordinary request. Perform
the driver's documented initialization as an explicit application or infrastructure step before starting
workers.

A supplied instance is borrowed by default and is never closed by RELKIT. A factory is owned by default;
owned resources require a `dispose` callback and are released once. Set `ownership` explicitly when the
default does not match the real lifecycle.

Prefer a dedicated AI database. Sharing a physical database requires a compatible underlying client,
isolated tables or schemas, a restricted role, and migration filters that keep checkpoint/store objects out
of the application Drizzle lifecycle. A RELKIT Redis cache provider is not a Redis saver or store.

## Resume the same business thread

Every initial run, observation, stop, steering operation, follow-up, approval, and continuation supplies a
caller-owned `threadId`. RELKIT never derives one from input, remembers an implicit current thread, or
generates a fallback. Internal run, task, attempt, and operation IDs are separate.

After the graph persists its checkpoint and waiting contract, submit the exact declared reply on the same
thread with `{ resume: true }`. A boolean wait rejects text such as `"yes"`; RELKIT does not interpret it.
The runtime binds the continuation to the waiting revision, scope, action, policy, and response schema,
deduplicates an accepted receipt, and fences competing workers.

See [Threads and recovery](/docs/modules/ai/threads-recovery) for restart and external-effect safety, and
[Agent streaming](/docs/modules/ai/streaming) for the public event sequence.
