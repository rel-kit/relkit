Turn an existing function into a tool with `.asTool()` so an agent or MCP client can call it. Keep the business logic in the function and add a description and execution policy for AI callers.

<Callout type="note" title="Before you begin" icon="clipboard-check">
Start with an [installed minimal app](/docs/learn/create-an-app). Function-backed tools need no
LangChain integration. [MCP](/docs/modules/ai/mcp) and [native agents](/guides/ai/build-an-offline-agent) each add their own
selected dependencies when you choose those execution paths.
</Callout>

<Steps>
<Step>

## Define the function

This small function returns a greeting. In a real app, the function might look up a product or fetch an order the current user is allowed to see.

## Turn it into a tool

Import the function into a tool file and call `.asTool()`:

<include
  source="templates/default/v1/agent/src/services/hello/tools/lookup.tool.ts"
  lang="ts"
  meta='title="src/services/hello/tools/lookup.tool.ts"'
>
  /_snippets/source/templates/default/v1/agent/src/services/hello/tools/lookup.tool.ts
</include>

The tool accepts the same input and returns the same output as `hello`. The function remains callable by the rest of your app.

Use a normal `defineFunction` here. Event-only functions created with `defineEventFunction` cannot become tools.

</Step>
<Step>

## Use the tool

Add `lookup` to an [agent's tools](/docs/modules/ai/agents), or call `hello.lookup` from [an MCP client](/docs/modules/ai/mcp). Both use the same greeting function.

`.asTool()` and [`defineTool({ target: hello, ... })`](/docs/modules/ai/tools) are alternatives; you do not need both. Both expose the tool to MCP by default. Set `mcp: false` if the tool should be available only inside your app.

</Step>
</Steps>
