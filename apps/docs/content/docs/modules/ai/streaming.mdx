  first. For a browser caller, also complete [frontend client setup](/docs/modules/client) in its
  own package.

## Expose the declared controls

Client-exposed agents require an agent-state profile. `useAgent` exposes only controls declared by the
agent: steer, follow-up, stop, and approval/denial. An agent with a reachable approval-requiring tool
must declare the approve capability.

Pass an application-owned thread ID, for example `<OrderSupport threadId="support:order-demo-1" />`,
and retain it when reopening the same conversation. The hook does not create a thread on mount.
The selected backend declaration determines the available client operations:

| Backend declaration                               | Typed frontend behavior                                                     |
| ------------------------------------------------- | --------------------------------------------------------------------------- |
| `chat` mapping                                    | `send(message, { threadId })`; other agents use `run(input, { threadId })`. |
| Input and output schemas                          | Typed initial input and `output`.                                           |
| `client.state`, tool contracts, and custom events | Selected `values`, `toolCalls`, `timeline`, and event payloads.             |
| Declared controls                                 | Stop, steer, follow-up, approval, and denial methods only when supported.   |
| A graph continuation schema                       | `run(reply, { threadId, resume: true })` for the same waiting thread.       |

`observe({ threadId })` reconnects to an existing authorized thread. Never replace an uncertain run
by choosing a new thread ID. See [threads and recovery](/docs/modules/ai/threads-recovery) and
[approvals](/docs/modules/ai/approvals) for those flows. Generic HTTP streams use
[`useStream`](/docs/modules/http/streaming#use-from-the-frontend) instead.

## Observe without blocking execution

Persistent journal acceptance is separate from browser delivery. Slow observers detach with
`SLOW_CONSUMER` and recover from the journal; they never backpressure model or tool execution.
Browser projections contain validated public messages, parts, progress, tool data, and results—not
provider payloads, internal prompts, credentials, private context, or private reasoning.

Agent content streams and task progress/streams are separate contracts. Use a task job's run ID and generated
job client for background work; do not treat an agent graph state or realtime channel as a task run.
