Add a greeting assistant to your existing RelKit app. It combines a native LangChain model, native
middleware and tool, and a RelKit function-backed tool. The small example runs without a database,
network request, or paid model call.

Create the files below, or update them if they already exist. Run commands from your app's root. The offline test uses `@relkit/testing`, included in generated RelKit apps.

```sh
bun add langchain @langchain/langgraph
```

## Test without a model key

The test scripts a tool call and a final answer, while running the real greeting function:

<include cwd lang="ts" meta='title="tests/unit/assistant.agent.test.ts"'>
  ../../templates/default/v1/agent/tests/unit/assistant.agent.test.ts
</include>

```sh
bun test ./tests/unit/assistant.agent.test.ts
```

Expect a passing test with the answer `Hello from the offline LangChain model.` This checks native model
execution, todo middleware, and RelKit tool registration; it does not measure how a production model
interprets questions.

## Use a production model

Skip this step if you only want the offline example. Install the LangChain model package for your
provider, construct its compatible chat model in server code, and pass that instance or a lazy factory to
`model`. Provider credentials remain server-only and live calls may cost money. For
[MCP only](/docs/ai/mcp), use the function-backed tool without adding an agent.

Do not put a key in the agent's instructions or commit it to source control. Tests should continue to
inject or declare deterministic native models explicitly; no environment name silently selects a paid
provider.

```sh
bun run check
bun run dev
```

Open your RelKit Inspector, normally at `http://localhost:3210`. Under **Agents**, select
`hello.assistant` to inspect its tools, middleware state, and execution. To let an external AI client call
the greeting function directly, follow [Tools over MCP](/docs/ai/mcp).
