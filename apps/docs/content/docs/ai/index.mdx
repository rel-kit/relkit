An AI agent uses a language model to decide how to complete a task. Tools let it do useful work in
your app: look up an order, search a catalog, or prepare a response using current data.

**RelKit agents run through native LangChain and LangGraph APIs.** RelKit connects those workflows to
your application's functions, validation, permissions, durable threads, and execution limits. Use
`defineAgent` for model-driven work, or `defineGraph` and `defineGraphNode` for explicit workflows.
Adding subagents, skills, memory files, or a backend to `defineAgent` selects native DeepAgents
behavior through the same declaration.

Use an agent when the next step depends on a user's question. Use an ordinary function when you already know the steps, such as calculating a total or saving an order.

## The AI APIs

Usually, adding tools to a model means writing argument schemas, dispatching tool calls, handling results, and controlling how long the model can keep working. RelKit lets you reuse validated functions as tools, choose which tools an agent can use, and set limits on each run.

| API                 | What you use it for                                                       |
| ------------------- | ------------------------------------------------------------------------- |
| `defineAgent`       | Set native model, tool, middleware, DeepAgents, and client behavior.      |
| `defineGraph`       | Register a typed native LangGraph workflow and its public result.         |
| `defineGraphNode`   | Validate graph-node state updates, routes, and human continuation.        |
| `defineTool`        | Give an existing function a tool name, description, and execution policy. |
| `function.asTool()` | Turn a function into a tool directly.                                     |
| `mcp`               | Choose whether a tool is available to external MCP clients.               |

The same tool can serve a RelKit agent and an external AI client through **Model Context Protocol (MCP)**. You do not need a RelKit agent just to expose tools over MCP.

## Native framework boundary

Pass compatible LangChain models, tools, and middleware directly—there is no public adapter wrapper.
RelKit function-backed tools remain native-compatible while preserving function execution, validation,
authorization, and tool policies. LangGraph owns scheduling and control flow; RelKit validates declared
state and public output around it.

## Observe durable execution

Client-exposed agents stream one canonical event history over HTTP iteration, AG-UI SSE, or WebSocket.
The typed client exposes messages, tools, progress, selected middleware state, waiting requests, nested
execution, and final output separately. Every run, observation, control, and continuation supplies an
application-owned `threadId`; mounting a hook never invents one or starts work.

See [Agent streaming](/docs/ai/streaming) and [Threads and recovery](/docs/ai/threads-recovery).

For the complete native boundary, continue with [Native runtime and DeepAgents](/docs/ai/native-runtime)
and [LangGraph, persistence, and resume](/docs/ai/graphs-persistence).

## Choose where to start

Follow the [greeting-assistant tutorial](/docs/ai/first-agent) to add an agent to an existing app and test it without a model API key.

Already have application functions? [Turn one into a tool](/docs/ai/function-tools), then [give it to an agent](/docs/ai/agents) or [connect an MCP client](/docs/ai/mcp).

In the Inspector, open **Agents** to review an agent's tools and limits, or **Tools** to review the functions each tool calls.

<Callout type="warn" title="Review MCP access">
  MCP is enabled by default, and tools are exposed unless you set `mcp: false`. Before making your
  app reachable by other users, review tool visibility and protect `/mcp`. An agent's tools list
  does not restrict the MCP endpoint.
</Callout>
