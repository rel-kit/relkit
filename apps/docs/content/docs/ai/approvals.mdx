---
title: Tool approvals
description: Require a trusted decision before a tool performs a sensitive action.
---

Use approvals when a tool can do something the user should confirm, such as cancel an order or send a message. The model may propose the action; it must not approve itself.

AI SDK documents a separate [needsApproval flow](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling#tool-execution-approval). `needsApproval` is not a RelKit tool option; use the policies and invocation callbacks below.

## Choose a policy

`defineTool.approval` and `.asTool({ approval })` accept exactly three policy strings:

The examples below are alternatives: choose the policy that fits each tool.

| `approval` | Behavior                                                                       |
| ---------- | ------------------------------------------------------------------------------ |
| `never`    | No separate approval decision is required.                                     |
| `on-write` | Require approval for `write` and `external` actions, but not `none` or `read`. |
| `always`   | Require approval for every call, including reads.                              |

Declare `sideEffect` accurately. A write incorrectly marked as a read can skip an intended `on-write` approval.

## Use an approval callback

The tool's `approval` policy is not a function. The callback goes in the second argument of **`tool.invoke()`**, where your application supplies the decision for that call.

The callback may return `true` or `"approved"` to allow execution, and `false` or `"denied"` to stop it. It may also return a Promise of any of those values. It receives `{ toolId, sideEffect, policy }`; capture the specific action's arguments from your calling code.

## Agent and MCP limitations

The standard `context.agents` call does not currently accept a custom approval callback or offer a built-in confirmation-and-resume flow. Do not expect adding an approval policy to a tool to create that flow for an agent. The [agent test helper](/docs/api/testing) can supply scripted approvals for tests.

Over [MCP](/docs/ai/mcp#protect-access), approval-required calls are currently rejected; there is no MCP approval-and-resume flow. Keep these tools out of MCP with `mcp: false` if clients cannot use them.
