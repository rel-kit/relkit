title: Request inference and explicit mapping
description: Learn where RELKIT reads path, query, body, header, cookie, and multipart values before validation.

A route maps transport data into reusable function input. The handler receives validated business data;
it does not parse a framework request object.

## Default inference

When `request` is omitted, RELKIT projects an object input schema by method:

<Tabs items={["Read methods", "Write methods"]}>
  <Tab value="Read methods">
    For `GET`, `HEAD`, `DELETE`, and `OPTIONS`, dynamic path names consume matching properties and remaining
    properties become query parameters.

    ```sh title="Terminal"
    curl "http://localhost:3000/hello?name=Ada"
    ```

  </Tab>
  <Tab value="Write methods">
    For `POST`, `PUT`, and `PATCH`, dynamic path names consume matching properties and remaining properties
    come from a JSON body.

    ```sh title="Terminal"
    curl -X POST "http://localhost:3000/echo" \
      -H "content-type: application/json" \
      -d '{"message":"hello"}'
    ```

  </Tab>
</Tabs>

An input schema without a usable object projection requires a complete explicit mapping.

## Map transport fields explicitly

Headers, cookies, renamed fields, transforms, multipart bodies, and non-object input require `http.input`.
The commerce route demonstrates an executable header/body mapping:

<include cwd lang="ts" meta='title="examples/commerce/src/routes/orders/route.ts"'>
  ../../examples/commerce/src/routes/orders/route.ts
</include>

An explicit mapping replaces inference entirely; the two are never merged. Sources include `path`,
`pathSegments`, `query`, `header`, `cookie`, `body`, `wholeBody`, `multipart`, `multipartAll`, and
`constant`. Use `http.nested` for nested objects and `http.transform` only with a serializable,
compiler-known transform descriptor.

## Verify success and failure

<Steps>
  <Step>
    ### Send all required sources

    ```sh title="Terminal — relkit-orders"
    curl -i -X POST "http://localhost:3000/orders" \
      -H "content-type: application/json" \
      -H "idempotency-key: order-1" \
      -H "x-customer-email: ada@example.com" \
      -d '{"sku":"book","quantity":2}'
    ```

  </Step>
  <Step>
    ### Remove one required header

    Repeat the request without `idempotency-key`. Expect `422`; mapping or validation fails before the
    function handler runs.

  </Step>
</Steps>

The optional request view preserves unmatched params, repeated query/header values, cookies, and native
transport details for middleware. Direct, job, event, tool, and agent calls never receive a fabricated
HTTP request.
