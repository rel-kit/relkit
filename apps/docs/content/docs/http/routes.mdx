Every `src/routes/**/route.ts` file defines a URL path. Named exports define methods. You do not repeat
`path` or `method` inside `defineRoute`.

## Path conventions

| File                                    | Runtime path               | Matching input             |
| --------------------------------------- | -------------------------- | -------------------------- |
| `src/routes/route.ts`                   | `/`                        | none                       |
| `src/routes/orders/route.ts`            | `/orders`                  | none                       |
| `src/routes/orders/[orderId]/route.ts`  | `/orders/:orderId`         | `orderId: string`          |
| `src/routes/files/[...parts]/route.ts`  | `/files/*parts`            | `parts: readonly string[]` |
| `src/routes/docs/[[...parts]]/route.ts` | `/docs` and `/docs/*parts` | optional segment array     |

Valid method exports are `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, and `OPTIONS`. Helper exports are
allowed, but default route exports and legacy `*.route.ts` files fail with source-located migration advice.

## Add another method

<Steps>
  <Step>
    ### Export the method from the existing file

    In `src/routes/status/route.ts`, duplicate the existing `GET` export, rename the copy to `HEAD`, and
    keep the target as `hello`. The two named exports now describe two HTTP operations in one route file.

  </Step>
  <Step>
    ### Check route discovery

    ```sh title="Terminal — relkit-orders"
    bun run check
    bun run graph
    curl -I "http://localhost:3000/status"
    ```

    `HEAD` invokes the target normally but removes the response body. The graph and OpenAPI document should
    contain both operations.

  </Step>
</Steps>

## Matching and identity

Static routes win over dynamic routes, then required catch-all, then optional catch-all. The compiler
normalizes paths and rejects collisions before activation. Optional catch-all creates two runtime
registrations but remains one authored descriptor and one generated-client operation.

Route IDs are source-scoped when omitted. Add an explicit ID only when moving the file or export must not
change graph and deployment identity. Route groups, parallel routes, and intercepting routes are not
supported.
