## Multipart uploads

Use `z.file` for the Web `File` type and explicitly map form fields. Uploads are buffered.

<include cwd lang="ts" meta='title="examples/commerce/src/routes/uploads/route.ts"'>
  ../../examples/commerce/src/routes/uploads/route.ts
</include>

`http.multipart(name)` reads one value; `http.multipartAll(name)` reads repeated values. Set per-file
`maxBytes`/`mediaTypes` in `z.file` and per-route `maxBodyBytes` when the server default is too broad.
The global default is 1 MiB. Missing fields, unsupported media types, oversized files, and oversized
bodies return bounded `422` errors. Streaming upload APIs are not currently exposed.

## Middleware order

1. Framework request setup, correlation, security, and body-size protection.
2. Rate limiter.
3. Matching path-scoped middleware in canonical middleware-ID order.
4. Request mapping, input validation, and admission.
5. Ordered service middleware, when the route targets a service member.
6. Target invocation through the common function engine.

Define HTTP middleware independently from routes. It receives the native Hono context, `next`, and
ZSYS `signal`, `env`, `log`, and `time` utilities:

```ts
export default defineMiddleware("/orders/*", async (context, next, zsys) => {
  zsys.log.info("checking order request");
  if (!context.req.header("authorization")) return context.json({ error: "unauthorized" }, 401);
  await next();
  context.header("x-orders-policy", "checked");
});
```

Supported scopes are `*`, static segments, `:param`, and a trailing `*`. Middleware is discovered
automatically; routes do not carry middleware arrays. Returning a `Response` short-circuits, while
`await next()` enables Hono onion-style response modification.

## Rate limiting

```ts
rateLimit: {
  limit: 100,
  windowMs: 60_000,
  key: http.header("x-api-key"),
  store: apiRateLimitCache,
}
```

Keys may come from path, query, header, cookie, or constants. Callback/body-dependent keys are rejected.
Local development may omit the store and use generation-local memory. Production check/build/start/deploy
requires an explicit shared numeric cache because process memory is neither distributed nor restart-safe.
Responses include standard limit/retry headers, a safe JSON `429`, OpenAPI metadata, request records,
and trace attributes.
