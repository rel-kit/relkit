Use `relkit-orders` after [adding the Orders endpoint](/docs/start/first-route) to the certified minimal app.
That chapter creates this route from maintained API-candidate sources. Follow one `POST /orders` request from JSON to a validated
function result and verify both accepted and rejected input. Run commands from the app root.

## Select the public operation

The Orders domain calculates a price in `createOrder`. Its service exposes that operation to
the route. Read the **existing** `src/services/orders/service.ts`:

<include cwd lang="ts" meta='title="src/services/orders/service.ts"'>
  ../../templates/default/v1/api/src/services/orders/service.ts
</include>

The service is the public boundary. A route imports the service, not a private function file.
The route's folder supplies `/orders`; its named `POST` export supplies the HTTP method:

<include cwd lang="ts" meta='title="src/routes/orders/route.ts"'>
  ../../templates/default/v1/api/src/routes/orders/route.ts
</include>

`member: "createOrder"` selects the public operation. `successStatus: 201` changes only the
successful response status; RELKIT infers the JSON input and output contracts from the function.
The [endpoint chapter](/docs/start/first-route) changes the price rule without editing this route.

## Send a request and inspect the result

Start the app with `bun run dev`. In another terminal, send a valid request:

```sh title="Terminal — relkit-orders"
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"route-1","sku":"book","quantity":3}'
```

Expect HTTP `201` and `totalCents: 300`. The starter's HTTP test checks the same status and
body in process. Create `tests/integration/orders.route.test.ts` from this source:

<include cwd lang="ts" meta='title="tests/integration/orders.route.test.ts"'>
  ../../templates/default/v1/api/tests/integration/orders.route.test.ts
</include>

Run `bun test tests/integration/orders.route.test.ts`. Then send `quantity: 0`; the running
server returns HTTP `422` before the handler creates an order. The test harness also maps
function-input validation to `422`, but it does not reproduce every middleware or transport
behavior. Check security policy and alternate transports against the running server.

## Inspect the generated contract

Run `bun run check` and `bun run typecheck`, then open `/_relkit/v1/openapi.json` on the
running backend. Find `POST /orders`, its request fields, success response, and validation
response. Edit source to change the contract; do not edit `.relkit/generated` output.
Select the [optional Scalar UI](/docs/http/openapi) when you want an interactive reference.

For path parameters, headers, and cookies, continue with [Request mapping](/docs/http/requests).
