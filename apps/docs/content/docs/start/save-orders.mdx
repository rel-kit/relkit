The Orders route from [the previous chapter](/docs/start/first-route) only calculates a response.
Here you will store that result in SQLite and add `GET /orders/:orderId`. Stop `bun run dev`
before changing the database. Keep working in the same `relkit-orders` application.

## Add the local database

Scaffold the supported Drizzle service. This installs the compatible packages and creates an
`items` placeholder. **Replace** that placeholder with the Orders schema below; do not keep both.

```sh title="Terminal — relkit-orders"
bun run relkit add database --orm drizzle --dialect sqlite
```

Replace `src/database/schema/index.ts` with one Orders table. `orderId` is the unique key;
`ownerId` is empty until the next chapter adds sign-in. Existing anonymous demonstration orders
will not become anyone's private orders automatically.

## Migrate, run, and check

Replace the scaffolded `drizzle.config.ts` with this configuration. It refuses an unset or
in-memory path so the migration cannot quietly target the wrong database.

<include cwd lang="ts" meta='title="drizzle.config.ts"'>
  ../../apps/docs/examples/orders-tutorial/steps/persistence/drizzle.config.ts
</include>

Generate and review the initial SQL migration, then apply it and start the app:

Drizzle Kit's `migrate` command currently selects `better-sqlite3` in this Bun project.
Create `scripts/migrate.ts` to apply generated SQL with the Bun SQLite driver used by the app:

<include cwd lang="ts" meta='title="scripts/migrate.ts"'>
  ../../apps/docs/examples/orders-tutorial/steps/persistence/scripts/migrate.ts
</include>

```sh title="Terminal — relkit-orders"
export DATABASE_PATH=./orders.sqlite
bun --bun drizzle-kit generate --name=initial
bun scripts/migrate.ts
bun run check
bun run typecheck
bun run dev
```

In another terminal, submit a new order and read it back:

```sh title="Second terminal — relkit-orders"
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"saved-1","sku":"book","quantity":10}'
curl http://localhost:3000/orders/saved-1
```

Expect HTTP `201` with `totalCents: 900`; the GET response has `found: true` and the same
order. Restart `bun run dev` and repeat the GET: the result remains. Use a new `orderId` for
another POST because the database enforces uniqueness.

This chapter's API has no access control yet.
