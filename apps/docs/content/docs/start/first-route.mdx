---
title: First route
description: Define a validated function and expose it through a convention-derived HTTP route.
---

Create `src/functions/hello.function.ts`:

```ts
import { defineFunction } from "@zsys/app";
import { z } from "@zsys/schema";

export default defineFunction({
  input: z.object({ name: z.string().default("world") }),
  output: z.object({ message: z.string() }),
  handler: async ({ name }) => ({ message: `Hello, ${name}!` }),
});
```

Create `src/routes/hello/route.ts`:

```ts
import { defineRoute } from "@zsys/app";
import hello from "../../functions/hello.function.js";

export const GET = defineRoute({ target: hello });
```

The file supplies `/hello`; the named export supplies `GET`. Because this is a `GET`, the remaining
object input property becomes `?name=`. Start everything and call it:

```sh
bun run dev
curl "http://localhost:3000/hello?name=ZSYS"
```

The response is `{ "message": "Hello, ZSYS!" }`. The compiler derives safe source-scoped IDs from the
file and export. Add an explicit ID when a descriptor must keep its graph and deployment identity after
a source move; durable application, event, job, bucket, and cache descriptors always keep explicit IDs.
