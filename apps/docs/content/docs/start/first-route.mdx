This chapter continues the `relkit-orders` app from [Create and run an application](/docs/start/create-an-app).
You will change the price for bulk orders and verify both successful and invalid requests. Keep `bun run dev`
running and use a second terminal for commands.

## Follow the request

The path and HTTP method come from `src/routes/orders/route.ts`. The route selects the public
`createOrder` operation and returns `201` after it succeeds:

<include cwd lang="ts" meta='title="src/routes/orders/route.ts"'>
  ../../templates/default/v1/api/src/routes/orders/route.ts
</include>

The service exposes `createOrder` and `priceOrder` from the Orders domain:

<include cwd lang="ts" meta='title="src/orders/service.ts"'>
  ../../templates/default/v1/api/src/orders/service.ts
</include>

`createOrder` validates `orderId`, `sku`, and a positive integer `quantity`, then invokes `priceOrder`.
That function owns the price rule. The route stays small so the same behavior can serve other callers.

```text
POST /orders → route → Orders service → createOrder → priceOrder → validated JSON
```

## Change one rule

Open the **existing** `src/orders/functions/price-order.function.ts`. Replace its handler with the
source below. Orders of 10 or more units now cost 90 cents each; smaller orders still cost 100 cents
each. The input and output schemas remain unchanged.

<include cwd lang="ts" meta='title="src/orders/functions/price-order.function.ts"'>
  ../../apps/docs/examples/orders-tutorial/steps/endpoint/src/orders/functions/price-order.function.ts
</include>

The development server checks and reloads this source. Verify the changed price:

```sh title="Second terminal — relkit-orders"
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"bulk-1","sku":"book","quantity":10}'
```

Expect HTTP `201` and `totalCents: 900`. Then send an invalid quantity:

```sh title="Second terminal — relkit-orders"
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"bad-1","sku":"book","quantity":0}'
```

Expect a validation response, not an order. Run `bun run check` and `bun run typecheck` after the
change. `check` verifies the discovered route and function contracts; typecheck verifies TypeScript.

The response still disappears after each request because this chapter has no database.
