two accounts, so they do not alter the database used by `bun run dev`.

## Test the HTTP and database boundary

Replace the starter's `tests/integration/orders.route.test.ts` with this test. It migrates a
temporary SQLite database, signs up Alice and Bob, creates an order for Alice, checks Bob cannot
read it, and rejects invalid input. It also checks that a signed-out request receives `401`.

<include cwd lang="ts" meta='title="tests/integration/orders.route.test.ts"'>
  ../../apps/docs/examples/orders-tutorial/steps/tests/tests/integration/orders.route.test.ts
</include>

The test uses `createTestApplication` for the in-process HTTP boundary. It covers these paths in
the test harness; it does not prove every production server behavior. Keep the manual requests
from the previous chapters for the running backend.

## Run the checks

From the application root, with the migration files still present:

```sh title="Terminal — relkit-orders"
bun run check
bun run typecheck
bun run test
```

Expect all commands to exit `0`. If the integration test cannot find `drizzle/`, finish the
two migrations from the preceding chapters. If another test still asserts the starter's old
response shape, update that assertion to include `quantity` and stored behavior.
