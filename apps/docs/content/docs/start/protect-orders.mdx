This chapter extends the same SQLite-backed `relkit-orders` app. You will add a local Better Auth
service, then require a session for both Orders routes. A caller cannot choose an order owner in
request JSON; the server gets that identity from the session. Stop `bun run dev` before migrating.

## Add authentication to the existing database

The auth scaffold installs Better Auth and creates its service and `/api/auth` route. It reuses
the database service already in the app. It does not apply a migration or create a secret.

```sh title="Terminal — relkit-orders"
bun run relkit add auth --adapter better-auth --database-dialect sqlite
```

## Sign in and verify access

Run `bun run typecheck` and `bun run dev` in the terminal with the auth environment set. In
another terminal, first call `GET /orders/saved-1` without a cookie; expect HTTP `401`.
Then create a local account and save its cookie:

```sh title="Second terminal — relkit-orders"
auth_cookies=$(mktemp -t relkit-orders-cookies)
curl -i -c "$auth_cookies" http://127.0.0.1:3000/api/auth/sign-up/email \
  -H 'content-type: application/json' -H 'origin: http://127.0.0.1:3000' \
  --data '{"name":"Demo","email":"demo@example.com","password":"local-demo-password-123"}'
curl -i -b "$auth_cookies" -X POST http://127.0.0.1:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"private-1","sku":"book","quantity":3}'
curl -b "$auth_cookies" http://127.0.0.1:3000/orders/private-1
```

Expect sign-up and POST success, followed by `found: true`. A different signed-in account
receives `found: false` for `private-1`.
