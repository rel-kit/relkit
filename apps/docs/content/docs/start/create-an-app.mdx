You will build a RELKIT API in this series. This chapter generates `relkit-orders`, starts it locally,
and proves it answers a request. You need Bun 1.3.10 and a terminal; no database, cloud account, or
deployment tool is needed yet.

## Create the project

Run the generator in the directory where you want the new project. The packaged capability table
currently offers the certified `minimal` template with examples, no jobs service, no cloud, and no
deployment adapter. Accept the suggested destination, then confirm creation:

```sh title="Terminal — parent directory"
bunx create-relkit@latest relkit-orders
cd relkit-orders
cp .env.example .env
```

The generator installs dependencies, checks the initial app, and prepares its first development
snapshot. The minimal template contains the Hello domain and route.
The commands from here onward run in `relkit-orders`.

When another tool owns installation, pass `--no-install`, then run the exact finite workflow printed
by the generator:

```sh title="Terminal — generated project"
bun install
bunx --no-install relkit dev --prepare
```

Preparation validates the installed project, publishes an unchanged-development snapshot, and exits
without opening the backend or Inspector ports. The next `bun run dev` still verifies that snapshot
against the current source, dependencies, toolchain, and runtime environment before activation.

Interactive creation asks for a missing project name, filters choices through the same packaged
capability table used by headless creation, and asks for the destination before final confirmation.
Uncertified explicit combinations fail before staging or installation. Git initializes by default;
use `--no-git` to disable it. Add more artifacts afterward with
[`relkit add`](/docs/start/add-artifacts).

## Run it and make a request

Start the app and keep this terminal open:

```sh title="Terminal — relkit-orders"
bun run dev
```

The backend normally listens on `http://localhost:3000`; the Inspector runs on
`http://localhost:3210`. In a second terminal, invoke the generated Hello route:

```sh title="Second terminal — relkit-orders"
curl -i 'http://localhost:3000/hello?name=RELKIT'
```

Expect HTTP `200` and `{"message":"Hello, RELKIT!"}`.

If startup fails, run `bun run check` and read its first diagnostic. The template's cloud and
deployment choices default to `none`; this local path needs no AWS or Pulumi credentials.

## What the starter gave you

- `src/hello/functions/` contains the greeting behavior.
- `src/hello/service.ts` exposes the public Hello operation.
- `src/routes/hello/route.ts` connects `GET /hello` to that service.
- `relkit.config.ts` sets the server and Inspector defaults.

You edit these TypeScript files; `.relkit/generated` is checked output, not an authoring directory.
