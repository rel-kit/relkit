This guide creates `relkit-orders`, the application used throughout the documentation. It uses the `api`
template but explicitly disables cloud provisioning and deployment, so the complete Start journey runs
without AWS credentials, Pulumi, or paid resources.

## Before you start

RELKIT projects use Bun for dependency installation, scripts, tests, and the development process. Install
[Bun 1.3.10](https://bun.sh/docs/installation), then confirm the exact version:

```sh title="Terminal"
bun --version
```

Expected output is `1.3.10`. If another version is active, switch before generating the project.

<Callout type="info" title="Cloud deployment is optional">
  Pulumi and AWS credentials are needed only for the optional deployment guide. They are not
  prerequisites for creating, developing, testing, checking, or building this application.
</Callout>

## Generate the project

<Steps>
  <Step>
    ### Run the generator

    Execute this command from the directory that should contain the new project:

    ```sh title="Terminal"
    bunx create-relkit@latest relkit-orders --template api --cloud none --deploy none
    ```

    The generator validates the destination before writing, installs dependencies, runs initial checks,
    and does not leave a partial project after a failure.

  </Step>
  <Step>
    ### Load the local defaults and run diagnostics

    ```sh title="Terminal"
    cd relkit-orders
    cp .env.example .env
    bun run relkit doctor --no-pulumi
    bun run check
    ```

    The API template declares an event provider, so `.env.example` supplies its non-secret local endpoint,
    bus name, region, and log level. `--no-pulumi` tells `doctor` this journey does not require Pulumi or AWS
    credentials. `check` compiles descriptors and writes the checked graph and diagnostics under
    `.relkit/generated`. Both commands must exit `0`.

  </Step>
</Steps>

## Understand the generated files

  <File name="relkit.config.ts" />

      <File name="hello.function.ts" />

        <File name="create-order.function.ts" />

      </Folder>
    </Folder>
    <Folder name="routes" defaultOpen>
      <Folder name="hello">
        <File name="route.ts" />
      </Folder>
      <Folder name="echo">
        <File name="route.ts" />
      </Folder>
      <Folder name="orders">
        <File name="route.ts" />
      </Folder>
    </Folder>
    <Folder name="events">
      <File name="order-created.event.ts" />
    </Folder>
    <Folder name="services">
      <File name="orders.service.ts" />
    </Folder>
  </Folder>
  <Folder name="tests">
    <Folder name="unit" />
    <Folder name="integration" />
  </Folder>
  <File name="package.json" />
  <File name="tsconfig.json" />
</Files>

- `relkit.config.ts` declares environment contracts, providers, server settings, and deployment choices.
- `.env.example` documents safe local defaults; `.env` is your ignored runtime copy. Do not commit secrets.
- `src/functions` contains validated behavior; functions do not receive HTTP request objects.
- `src/routes` maps filesystem paths and HTTP method exports to function targets.
- `tests/unit` invokes functions directly; `tests/integration` uses the in-process HTTP application.
- `tsconfig.json` maps `@app/*` to `src/*`. Import application modules as
  `@app/functions/hello.function.js` instead of counting `../` segments; keep `.js` for emitted ESM.
- `.relkit/generated`, `.relkit/build`, `.relkit/state`, and `.relkit/observability` are derived or runtime
  directories. Do not edit them by hand.
