You will build an Orders API in this series. This chapter generates `relkit-orders`, starts it locally,
and proves it answers a request. You need Bun 1.3.10 and a terminal; no database, cloud account, or
deployment tool is needed yet.

## Create the project

Run the generator in the directory where you want the new project. Choose the `api` template, then
skip the optional add-artifact wizard so your files match this guide:

```sh title="Terminal — parent directory"
bunx create-relkit@latest relkit-orders --template api
cd relkit-orders
cp .env.example .env
```

The generator installs dependencies and checks the initial app. The API template already contains
Hello, Echo, and Orders; later chapters **extend those files** rather than create a second Orders domain.
The commands from here onward run in `relkit-orders`.

## Run it and make a request

Start the app and keep this terminal open:

```sh title="Terminal — relkit-orders"
bun run dev
```

The backend normally listens on `http://localhost:3000`; the Inspector runs on
`http://localhost:3210`. In a second terminal, ask the existing Orders route to price three books:

```sh title="Second terminal — relkit-orders"
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"order-1","sku":"book","quantity":3}'
```

Expect HTTP `201` and JSON containing `orderId: "order-1"`, `sku: "book"`, and
`totalCents: 300`. This route calculates a response but does **not** save the order yet.

If startup fails, run `bun run check` and read its first diagnostic. The template's cloud and
deployment choices default to `none`; this local path needs no AWS or Pulumi credentials.

## What the starter gave you

- `src/orders/functions/` contains pricing and order creation behavior.
- `src/orders/service.ts` selects the Orders operations other code may use.
- `src/routes/orders/route.ts` connects `POST /orders` to that service.
- `relkit.config.ts` sets the server and Inspector defaults.

You edit these TypeScript files; `.relkit/generated` is checked output, not an authoring directory.
