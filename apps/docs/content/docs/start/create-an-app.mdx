This guide creates `relkit-orders`, the local application used in the Start guides. It uses the `api`
template with Hello, Echo, and Orders domains and skips deployment prerequisites during generation.
No Start command provisions cloud resources: you need no AWS credentials, Pulumi, or paid resources.

You will create the app here, [run and add a route](/docs/start/first-route), then learn the
[local development loop](/docs/start/local-development). After that, [Service](/docs/service) explains
the architecture and the capability guides show how to extend your own application. Their examples
may come from other repository applications; they are not all generated into this starter.

## Before you start

RELKIT projects use Bun for dependency installation, scripts, tests, and the development process. Install
[Bun 1.3.10](https://bun.sh/docs/installation), then confirm the exact version:

```sh title="Terminal"
bun --version
```

Expected output is `1.3.10`. If another version is active, switch before generating the project.

<Callout type="info" title="Cloud deployment is optional">
  Pulumi and AWS credentials are needed only for the optional deployment guide. They are not
  prerequisites for creating, developing, testing, checking, or building this application.
</Callout>

## Generate the project

<Steps>
  <Step>
    ### Run the generator

    Execute this command from the directory that should contain the new project:

    ```sh title="Terminal"
    bunx create-relkit@latest relkit-orders --template api
    ```

    The generator validates the destination before writing, installs dependencies, runs initial checks,
    and does not leave a partial project after a failure.

  </Step>
  <Step>
    ### Load the local defaults and run diagnostics

    ```sh title="Terminal"
    cd relkit-orders
    cp .env.example .env
    bun run relkit doctor --no-pulumi
    bun run check
    ```

    `.env.example` supplies only a safe log-level default. `--no-pulumi` tells `doctor` this journey does
    not require Pulumi or AWS credentials. `check` compiles descriptors and writes the checked graph and
    diagnostics under `.relkit/generated`. Both commands must exit `0`.

    Cloud and deployment default to `none`, so the generated package and `defineApp` configuration omit AWS
    and Pulumi. Add `--cloud aws --deploy pulumi` only for an explicitly authorized deployment path.

  </Step>
</Steps>

- `relkit.config.ts` declares environment contracts, providers, server settings, and deployment choices.
- `.env.example` documents safe local defaults; `.env` is your ignored runtime copy. Do not commit secrets.
- `src/hello`, `src/echo`, and `src/orders` are domains. Each domain has one `service.ts` boundary and
  keeps its functions, events, errors, and other owned artifacts beneath that domain. The service
  selects the operations other code may consume; it is not a second copy of the handlers.
- `src/routes` maps filesystem paths and HTTP method exports to public service operations.
- `src/platform` contains shared infrastructure configuration such as the environment contract.
- `tests/unit` invokes functions directly; `tests/integration` uses the in-process HTTP application.
- `tsconfig.json` maps `@app/*` to `src/*`. Import application modules as
  `@app/hello/service.js` instead of counting `../` segments; keep `.js` for emitted ESM.
- `.relkit/generated`, `.relkit/build`, `.relkit/state`, and `.relkit/observability` are derived or runtime
  directories. Do not edit them by hand.

For the architecture behind this layout, start with [Service](/docs/service). Learn
[what a domain owns](/docs/service/domains) and [where to add each kind of code](/docs/service/organization)
before expanding the app with more capabilities.
