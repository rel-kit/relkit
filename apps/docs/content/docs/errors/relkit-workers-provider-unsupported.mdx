**Provider does not run on Cloudflare Workers.**

## What happened

`relkit check` found a wrangler configuration (`wrangler.jsonc`, `wrangler.json` or `wrangler.toml`) in the project and a used provider profile whose provider needs a local filesystem or a long-lived process: the local provider, a job or event provider that needs its own worker process, or no provider at all, which falls back to local state. A Worker has no filesystem, runs only while a request or event is handled, and runs as many isolates as traffic needs.

## What to do

Select a provider that runs on Workers for the profile, as the message names: the durable Postgres backend from `@relkit/postgres` for jobs and events (the Worker runs them from Cloudflare Queues and Cron Triggers), a Durable Object (`durableObjectRealtime()`) for realtime, a Workers KV binding (`kvBinding()`) or Redis over an `https://` URL for caches, an R2 binding (`r2Binding()`) or S3 for buckets, all from `@relkit/cloudflare` unless noted. Agent state has no Workers provider yet. Or deploy the app to a container target such as Railway and remove the wrangler configuration.

Reported by `@relkit/cli`, `relkit/diagnostics`.
