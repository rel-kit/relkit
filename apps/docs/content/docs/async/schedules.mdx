A schedule is an option on a job that enqueues input on a calendar. The complete guide now lives under
[Jobs → Schedules](/docs/jobs/schedules), alongside job definition, retries, and idempotency.

## Read the schedule contract

<include cwd lang="ts" meta='title="src/receipts/jobs/send-receipt.job.ts — schedule"'>
  ../../examples/commerce/src/receipts/jobs/send-receipt.job.ts#receipt-schedule
</include>

Each entry supplies a stable ID, five-field cron, explicit timezone, static JSON input, and overlap policy.
In the current runtime, overlap controls enqueue callbacks, not the lifetime of the target execution.
The example's constant order ID also shares the job's 24-hour local idempotency window, so hourly
enqueue attempts do not imply a fresh receipt every hour.

## Verify timing and recovery separately

Run the application checks after editing the descriptor:

```sh
bun run check
bun run typecheck
```

Then follow [Schedules](/docs/jobs/schedules) to test input, clock boundaries, overlap, and missed firings.
The local scheduler does not guarantee catch-up across a restart. The [first-job test](/docs/jobs/first-job)
proves queue execution and local duplicate protection; it does not start schedules automatically.
