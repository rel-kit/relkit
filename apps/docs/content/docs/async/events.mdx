An event is a fact that already happened, such as `orders.created`. Publishers do not choose or wait for every
consumer. Independent listeners can react without adding their work to the publisher's request path.

## Define the event contract

</include>

The stable ID is the topic contract. `version` allows consumers to distinguish incompatible payload shapes.
The schema validates every publish and delivery. `sensitiveFields` marks payload paths for redaction in logs,
traces, inspector previews, and diagnostics.

Name events in past tense. `orders.create` is a command; `orders.created` is a fact. Do not publish a broad
“updated” event when consumers require specific business meaning.

## Publish from a function

<Steps>
  <Step>
    ### Declare the event dependency

    Add the event descriptor under `dependencies.events` on the publishing function. This authorizes the
    context client and adds the graph edge used by deployment.

  </Step>
  <Step>
    ### Publish validated data

    The order function calls `context.events.orderCreated.publish(payload)`. Completion means the provider
    accepted the event; it does not mean every listener finished.

  </Step>
  <Step>
    ### Assert publication locally

    Use `invokeFunction` with the deterministic event fake, then inspect the published event ID, version, and
    payload. No EventBridge credentials are needed.

  </Step>
  <Step>
    ### Inspect the graph

    ```sh title="Terminal — relkit-orders"
    bun run check
    bun run relkit graph print
    ```

    Confirm the publisher edge and every discovered listener before deployment.

  </Step>
</Steps>

## Evolve payloads safely

Consumers may deploy independently and durable providers may retain older payloads. Adding an optional field
is often compatible; removing or reinterpreting a field is not. Increment the event version for an incompatible
shape and migrate listeners deliberately. Do not reuse the same version for two meanings.

## Delivery expectations

Event acceptance is asynchronous. Providers may deliver at least once, out of order, or after delay. Put a
stable domain identifier in the payload so listeners can deduplicate or reconcile. Do not assume that two
events published consecutively will finish in that order unless the selected provider and partition key make
that guarantee explicit.

<Callout type="warn" title="Sensitive metadata is not encryption">
  Redaction prevents common observability leaks. Use transport encryption, provider access control,
  and minimal payloads for actual confidentiality.
</Callout>
