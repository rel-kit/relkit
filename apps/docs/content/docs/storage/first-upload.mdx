Add product-image uploads to your existing RelKit app. You'll send two images to `POST /uploads`, store them in a private bucket, and find them in the Inspector.

Create the four files below. If your app already has an Assets service or an uploads route, merge these members into it. Run commands from your app's root.

## Configure storage

Install the local S3-compatible integration from your app root:

```sh title="Terminal — application root"
bun add @relkit/s3 @relkit/docker
```

In `relkit.config.ts`, import `s3` from `@relkit/s3`, `docker` from `@relkit/docker`, and
`env as binding` from `@relkit/app/config`. Create a `bucket` object inside `defineApp()` if the
app has none, then add this `assets` entry:

<include cwd lang="ts" meta='title="relkit.config.ts — bucket configuration"'>
  ../../examples/commerce/relkit.config.ts#storage-local-profile
</include>

`assets` starts a local MinIO recipe in development. The complete commerce application also has
other bucket profiles; this first upload needs only `assets`. Connected and cloud ownership
choices are described in [Define a bucket](/docs/storage/define).

## Upload two images

Check and start the app:

```sh
bun run check
```

```sh
bun run dev
```

The local MinIO recipe supplies generated binding-only credentials and loopback ports. Keep the app running
and open a second terminal in the app's root. `bun run dev --local=off` disables recipes and requires the
named connected/infrastructure values instead.

Place two small PNG images named `cover.png` and `detail.png` there. Keep their combined size below 1 MB for this request, then send:

```sh
curl -i http://localhost:3000/uploads \
  -F 'label=book-photos' \
  -F 'primary=@cover.png;type=image/png' \
  -F 'attachments=@detail.png;type=image/png'
```

Use your app's configured port if it differs from `3000`. Expect HTTP 200:

```json
{ "label": "book-photos", "files": ["cover.png", "detail.png"] }
```

## Check the stored files

Open your app's Inspector, normally at `http://localhost:3210`. Select **Buckets**, open `assets.objects`, and look for `cover.png` and `detail.png`. Click **Preview** beside either key to view its image.

Tests must provide explicit replacements for profile `assets`; no environment name installs a file fake.
You can now [read the files or create download links](/docs/storage/read-delete). Before deploying, review
ownership in [Integrations](/docs/integrations) and add authentication to the upload endpoint.
