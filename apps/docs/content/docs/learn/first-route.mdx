Add `POST /orders` to the application from [Create and run an API](/docs/learn/create-an-app).
You'll calculate an order's price, change the bulk-price rule, and check that invalid quantities are rejected.

<Callout type="note" title="Before you begin" icon="clipboard-check">
Keep `bun run dev` running in the same `relkit-orders` directory. Use a second terminal for requests.
</Callout>

## 1. Add the Orders domain [#add-the-orders-domain]

From the application root, scaffold the two functions and their service:

```sh title="Second terminal — relkit-orders"
bun run relkit add function price-order --create-service orders
bun run relkit add function create-order --service orders
```

The first command creates `src/services/orders/service.ts` and
`functions/price-order.function.ts` beneath that service. The second adds
`functions/create-order.function.ts` and exposes `createOrder` through `service.ts`.
Both functions start with placeholder schemas and handlers.

Replace the generated files with the examples below. If you prefer to create files manually,
add the same paths and contents instead of running these commands. If a file already exists,
edit it; `relkit add` does not overwrite it.

## 2. Follow the request [#follow-the-request]

The path and HTTP method come from `src/routes/orders/route.ts`. The route selects the public
`createOrder` operation and returns `201` after it succeeds. The service exposes `createOrder` and
`priceOrder` from the Orders domain.

`createOrder` validates `orderId`, `sku`, and a positive integer `quantity`, then invokes `priceOrder`.
That function owns the price rule. The route stays small so the same behavior can serve other callers.

```text
POST /orders → route → Orders service → createOrder → priceOrder → validated JSON
```

</Step>

The development server checks and reloads this source. Verify the changed price:

```sh title="Second terminal — relkit-orders"
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"bulk-1","sku":"book","quantity":10}'
```

Expect HTTP `201` and `totalCents: 900`. Then send an invalid quantity:

```sh title="Second terminal — relkit-orders"
curl -i -X POST http://localhost:3000/orders \
  -H 'content-type: application/json' \
  -d '{"orderId":"bad-1","sku":"book","quantity":0}'
```

Expect a validation response, not an order. Run `bun run check` and `bun run typecheck` after the
change. `check` verifies the discovered route and function contracts; typecheck verifies TypeScript.

The response still disappears after each request because this chapter has no database.
