Jobs are the public API for work that may outlive the request that started it. Define a typed task, expose it through a job, and let Relkit persist the run, retry transient failures, and report progress.

Tasks own execution code, schemas, retry policy, limits, and hooks. Jobs own the public API name, admission, schedules, service selection, and client projection. The task ID, version, input schema, output schema, and policy are part of the durable identity of a run.

## Defaults worth knowing

- A run accepts at most 1 MiB of input and returns at most 1 MiB of output.
- A progress or stream item is limited to 64 KiB.
- The default retry policy is three attempts, one-second initial delay, 30-second maximum delay, factor two, and no jitter.
- Run lists default to 25 items and accept at most 100.

Read [provider comparison](/docs/jobs/providers) before depending on durable sleep, native listing, or a schedule policy.

## Legacy API

The older function-target pages (`define`, `enqueue`, `first-job`, `retries`, `idempotency`, and `schedules`) remain available for migration. New code should use task-first jobs so task identity and compatibility checks are explicit.
