deployment preview only when cloud infrastructure is intentionally configured.

## Use the generated project commands

The templates expose the normal application lifecycle as package scripts:

<include cwd lang="json" meta='title="templates/default/v1/api/package.json"'>
  ../../templates/default/v1/api/package.json
</include>

During development, run the narrowest check that proves the change. Before releasing an application, run the
complete local sequence:

```sh title="Terminal — relkit-orders"
bun run check
bun run typecheck
bun run test
bun run build
bun run start
```

Building and starting do not create cloud resources. Deployment is a separate, explicit lifecycle.

## Match the repository gate before pushing

RELKIT contributors can run the same locally reproducible CI coverage before a push:

```sh title="Terminal — relkit repository"
bun run prepush
```

That command requires Docker and runs `verify`, container and local-service tests, deployment tests, Inspector
browser checks, and end-to-end tests. The opt-in AWS integration job and GitHub-hosted dependency review remain
CI-only because they require external credentials or platform context.
