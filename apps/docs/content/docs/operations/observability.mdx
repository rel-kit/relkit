RELKIT records HTTP requests and common-engine invocations with shared graph, trace, correlation, and invocation
identities. Handlers write structured records through `context.log`; functions, providers, jobs, events, tools,
and agents contribute correlated spans without importing a telemetry SDK.

Sentry and OTLP are independent integrations. Their credentials and endpoints use named binding references, so
resolved values do not enter the application graph or Inspector payloads.

## Understand capture order

```text title="Telemetry flow"
runtime event
→ canonical record
→ capture policy
→ redaction
→ bounded local persistence and live Inspector stream
→ root trace-consistent sampling
→ independent exporters
```

Local persistence happens before external sampling. With `traceRate: 0.25`, the bounded Inspector store can keep
a complete redacted local trace even when that trace is not selected for remote export. Child spans inherit the
root trace decision. Log export follows `minimumLogLevel`; errors and diagnostics are exported unsampled by
default.

`localRetention` bounds record count, age, and bytes. It is diagnostic evidence, not durable business storage.

## Redact before storage or export

`development-redacted` allows bounded content capture while replacing protected keys and known secret values.
`maxBytes` is required and prevents oversized content from being retained. Mode `off` omits protected payload
content entirely.

<Callout type="error" title="UI masking is too late">
  Authorization and cookie headers, environment secrets, provider credentials, request bodies,
  prompts, and model results must be removed or redacted before persistence, streaming, or exporter
  queues.
</Callout>

Use synthetic secrets in tests and assert that they do not appear in records, diagnostics, generated artifacts,
or exporter payloads. Redaction is a safety boundary, not permission to log credentials.

## Diagnose exporter health

Exporter fan-out is isolated. A failed Sentry or OTLP exporter cannot block application work or the other
exporter. Failures increment health counters and create redacted local-only diagnostics that are not sent back
through the failed exporter.

Start the app and follow one identifiable request:

```sh title="Terminal — relkit-orders"
bun run dev
curl "http://localhost:3000/hello?name=Telemetry" \
  -H "x-correlation-id: docs-telemetry"
```

Open the Inspector's **Requests** view, select `/hello`, and follow its trace, logs, graph hash, generation, and
activation fingerprint. If remote telemetry is silent, inspect exporter health, queue depth, failure count, and
drop count before assuming application capture failed.

AWS hosting routes redacted structured stdout to CloudWatch through the host integration. CloudWatch is host
logging, not an application exporter, so it does not belong under `telemetry.exporters`.
