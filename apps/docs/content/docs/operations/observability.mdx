---
title: Traces, logs, metrics, and redaction
description: Follow context through the common engine without exposing sensitive application data.
---

ZSYS uses OpenTelemetry-compatible trace, metric, and log concepts while keeping authored application
code independent of a specific backend. Every transport invokes the common function engine, which starts
spans, records declared and observed edges, propagates trace/correlation/causation context, and reports
completion outcomes.

HTTP request records include route/function identity, graph hash, status, duration, rate-limit outcome,
and bounded metadata. Jobs and events retain their instance/attempt identity. Resource, model, tool, and
child-function calls appear as correlated spans when available.

Redaction happens before data crosses an inspector or sink boundary. Environment secret values, protected
headers, request bodies under an off/redacted capture policy, and provider credentials must never appear
in graphs, generated artifacts, logs, traces, or error messages. Presentation changes must not weaken the
wire-level telemetry or redaction contracts.
