RELKIT uses OpenTelemetry-compatible trace, metric, and log concepts while keeping application handlers
independent of a specific backend. Every transport enters the common function engine, which creates spans,
propagates context, records observed calls, and reports completion outcomes.

## Follow a log into a trace

<Steps>
  <Step>
    ### Add structured context

    The generated hello function demonstrates the recommended logger in executable source:

    <include cwd lang="ts" meta='title="templates/default/v1/api/src/functions/hello.function.ts"'>
      ../../templates/default/v1/api/src/functions/hello.function.ts
    </include>

    Use stable event names and small structured fields. Do not interpolate secrets or entire request bodies.

  </Step>
  <Step>
    ### Send a correlated request

    ```sh title="Terminal — relkit-orders"
    curl "http://localhost:3000/hello?name=Telemetry" \
      -H "x-correlation-id: docs-telemetry"
    ```

  </Step>
  <Step>
    ### Locate the request, trace, and log

    In the inspector, filter Requests by `/hello`, open the latest record, follow its trace, and expand the
    function span. The structured log should carry the trace and correlation context without manual IDs in
    the handler.

  </Step>
</Steps>

## Understand recorded relationships

HTTP records include route/function identity, graph hash, status, duration, rate-limit outcome, and bounded
metadata. Jobs and events add instance and attempt identity. Resource, model, tool, and child-function calls
appear as correlated spans when available.

Descriptor `invoke` calls are observed relationships, not changes to the canonical graph. The graph remains
deterministic; runtime telemetry describes what actually happened during an invocation.

## Redaction boundary

<Callout type="error" title="Redact before export">
  Environment secrets, authorization/cookie headers, protected provider configuration, and request
  bodies under an off or redacted capture policy must be removed before inspector or sink output.
  Presentation-only masking is not sufficient.
</Callout>

Use `telemetry.bodyCapture` deliberately. Start with `mode: "off"`; enable bounded capture only for fields
that are safe and operationally necessary. Verify redaction using synthetic secret values before attaching
logs or JSON diagnostics to an issue.

```sh title="Terminal — relkit-orders"
bun run check
bun run test
```

Successful checks prove the telemetry configuration is graph-valid; tests should assert behavior and safe
metadata rather than unstable console formatting.
