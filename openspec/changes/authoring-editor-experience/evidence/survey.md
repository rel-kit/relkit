# Survey: what the editor suggests in RelKit's authoring APIs

Measured on this repository's source before any fix of this change (commit `758ee0e26`), with TypeScript 5.9.3 through its language service and TypeScript 7.0.2 through its language server. The fixture is the application in `tests/editor/fixture/`; `bun tests/editor/survey.ts` prints the table again.

## Result

|                                 | Positions | Works | Partly | Nothing | Misleading error |
| ------------------------------- | --------- | ----- | ------ | ------- | ---------------- |
| TypeScript 5.9 language service | 115       | 92    | 1      | 18      | 4                |
| TypeScript 7 language server    | 115       | 93    | 0      | 18      | 4                |

The two compilers agree on every position but one: for `execution` in `defineTask`, TypeScript 5.9 suggests `durable` only and TypeScript 7 suggests both values.

How a position is judged:

- **Suggestions.** The cursor is placed where a developer would ask for the list. `works` means every expected name is offered; `partly` some; `nothing` none. At a value outside quotes TypeScript lists the whole scope, so a known value counts only when it is ranked first.
- **Wrong value.** `works` means exactly one error whose text contains the expected names; `nothing` means no error; `misleading error` means several errors, or one that does not name them.
- TypeScript does not suggest a property that the object already has. The expected names of a position are therefore the ones not yet written.

## Causes of the 23 positions that do not work

### Typing defects in RelKit (12 positions)

1. **`defaults` in `defineApp` (7 positions), unknown `defineApp` option (1).** `DefineAppOptions` is `DescriptorMetadata & Providers & { … }`, and `Providers` is inferred from the whole options object.
   - Suggestions: while the cursor is inside the options object, TypeScript does not infer from any expression that encloses the cursor. `Providers` falls back to its constraint, and the type of a default becomes `string`. Result: the whole scope at an empty value, nothing inside quotes.
   - Wrong name: `Providers` captures `defaults` as written. Its intersection with the declared type of `defaults` has a property of type `"wrong" & "uploads"`, which is `never`, and an object type with such a property is `never` as a whole. Result: one error per property of `defaults`, the correct ones included, each `not assignable to type 'never'`.
   - Unknown option: it becomes part of `Providers` and is accepted. `caches: {}` beside a real provider is not an error; the application then fails when it is loaded (`Unknown defineApp option "caches"`).
   - The removed key `job` is suggested among the keys of `defaults`, because the type declares it as `never`.
   - Fixed by this change.
2. **A misspelled or removed `defineFunction` option (2).** The options object is itself a type parameter (`Options`), which the return type needs for the declared errors and the tool metadata. An extra key is part of `Options`, so `timeout: 10_000` is accepted without an error; the function then fails when it is loaded. `publishes` is declared as `never` to reject it, so the editor suggests it, and using it gives five errors: one "No overload matches this call" and four in the handler, whose `context` loses its types. Proposed below.
3. **`dependencies` kinds in `defineFunction` (1), `execution` in `defineTask` on TypeScript 5.9 (1).** Both APIs are overloaded. For suggestions the editor reads the first overload that fits: for `dependencies` that is the overload without dependencies, where the property is `never`, so the list is the whole scope. Proposed below.

### Names that no type carries to the position (10 positions)

4. **Role and permission names in `access` (4).** The names are in the application's Better Auth file (`createAccessControl(statement)` and the plugin's `roles`). `access.roles` and `access.permissions` are `readonly string[]`. Nothing is suggested, and a misspelled name is not an error anywhere before a request: `defineFunction` only rejects a permission without a colon when the function is loaded, and at run time Better Auth answers "not allowed" for an unknown resource or action, so every caller, the owner included, gets a 403. Fixed by this change through the generated context registry.
5. **Profile names in `defineBucket`, `defineCache` and `defineEvent` (5).** The names are in `relkit.config.ts`. `profile` is `string`. `relkit check` and `relkit dev` report a profile that does not exist (`RELKIT_PROVIDER_PROFILE_UNKNOWN`). Proposed below.
6. **Path parameter names in `http.path()` (1).** The names are the folder names of the route file (`[orderId]`). `relkit check` reports a name that does not fit (`RELKIT_MAPPING_INCOMPATIBLE`). Proposed below.

Names that the generated registries already carry work: `context.env`, `context.database`, the session of `context.auth`, the event name of `defineEventFunction`, the services, functions and bucket IDs of `getRelkit()`, and the routes of the generated client. `relkit dev` writes the registries when a source file changes and `relkit check` writes them on every run; the three registry files of `.relkit/generated/` are tracked in a generated application, so a fresh clone has them. Without a registry the editor shows no suggestion for these names (`context.env.`, `context.database.`, `session.user.`, the event name, `getRelkit().functions.`, the client's services) and reports errors where the code uses them (`'context.database.orders' is possibly 'undefined'`, `Property 'user' does not exist on type '{}'`).

### TypeScript limitations (1 position)

7. **Input field names in `http.input({ … })` (1).** `http.input()` is a call of its own; the input type of the route's function does not reach its argument, so the keys are not suggested. A wrong key is still an error on the route. What to do instead: read the function's `input` schema, or let `relkit check` report the mismatch.

Two more limits hold everywhere and are not counted as defects: a property that is already written is not suggested again, and where a value is an identifier (`errors: [orderNotFound]`, `dependencies.events: { orderPlaced }`) the editor lists the whole scope, because any expression of the right type is valid there.

## Proposed, not done in this change

1. **Profile names in descriptors.** Generate the application's profile names into the context registry (`typeof import("relkit.config.js")` already types them) and type `profile` in `defineBucket`, `defineCache`, `defineEvent` and `defineChannel` from it, as this change does for `access`. It needs a generator change and new tracked output in every example and template, and a decision on what `profile` accepts in a library that has no application.
2. **Unknown `defineFunction` options.** Add a mapped type over the keys of `Options` that are not options, so an extra key is an error on that key, and give `publishes` a type whose name says what to use, as `NoProviderConfigured` does. The error text needs a decision, and `defineEventFunction`, `defineTask` and `defineJob` share the pattern.
3. **One signature for the other overloaded APIs.** `defineTask` has an overload per `execution`; on TypeScript 5.9 the editor suggests one value. The change made to `defineFunction` here may apply, but the two forms differ in the handler's context, so it needs its own type tests.
