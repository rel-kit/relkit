# Decisions

- Use the only active OpenSpec change, `add-services-and-simplify-authoring`, without asking for routine confirmation.
- Use Phase 1 (tasks 1.1–1.3) as the first bounded iterator unit because it is the contract/baseline/dependency-boundary gate preceding implementation phases.
- Keep all work in the normal checkout on `fix/add-services-and-simplify-authoring`; leave changes uncommitted and visible.
- Strict validation passed without artifact repairs, so task 1.1 is checked.
- Task 1.2 is checked because every requested baseline suite was run; the restart-job failure was repaired in the test harness and the isolated gate now passes.
- The restart worker now names the unused request parameter explicitly because ZSYS handlers receive `(input, request, context)`; the prior two-parameter declaration treated the absent request as invocation context and caused the defect/dead-letter failures.
- Read the structural/export and boundary guidance before implementation; defer package, workspace, TypeScript, Turbo, and scope-boundary edits to task 1.3.
- Task 1.3 uses `@zsys/invocation` as an internal dependency-neutral layer over `@zsys/contracts` and `@zsys/schema`; `@zsys/functions`, `@zsys/engine`, and `@zsys/tools` consume it, while `@zsys/services` consumes contracts/functions/invocation/schema and `@zsys/app` owns the public service dependency. No higher runtime package is introduced below the invocation layer.
- `@zsys/invocation` remains internal/fixture-forbidden but is explicitly exempted from the descriptor-package runtime-import rule so the shared kernel can be consumed without permitting application fixtures to import it. `@zsys/services` is added to the public descriptor/package scope and declaration checks.
- The `@zsys/services` shell remains behavior-free until task 3.x; the invocation shell now owns the task 2.1–2.2 shared kernel primitives. The existing wildcard workspace and generic `^build` Turbo graph are sufficient, so no speculative root config was added.
- The public-declaration guard was repaired at its root: structural `~effect/Effect` protocol names are not dependency imports, and private helper type literals are not public handler declarations. The scan now passes without changing the function API.
- No lifecycle hook was run because `openspec/linear.yaml` is not present; Wayfinder alignment remains skipped because no plan/traceability row names Wayfinder sources.
- Task 2.1 keeps `@zsys/invocation` below the engine and moves the reusable kernel primitives there; runtime-effect compatibility barrels preserve existing imports while the engine continues to own registry, provider, admission, tracing, and generation concerns.
- Task 2.1 deliberately does not add asynchronous dispatcher scope, standalone descriptor dispatch, identity binding, recursion protection, descriptor methods, or service behavior; those remain later task boundaries.
- Task 2.1 parity tests use the shared package directly and retain the existing runtime-effect and engine suites to prove no public invocation outcome changed.
- Task 2.2 keeps dispatcher state in `AsyncLocalStorage`: the active scope carries only the dispatcher and current parent metadata, while dispatch outside a scope creates a fresh standalone dispatcher. No mutable process-global default runtime is introduced.
- Task 2.2 gives standalone dispatch its own signal, wall-clock, structured logger, frozen environment, and guarded managed-dependency maps. Missing standalone clients normalize to `ZSYS_DEPENDENCY_NOT_CONFIGURED` instead of selecting an arbitrary application runtime; explicitly supplied client maps remain supported.
- Task 2.2 deliberately does not add canonical identity binding, recursion/cycle policy, engine scope wiring, descriptor methods, observed call edges, or public authoring migration; those remain tasks 2.3–2.7.
- Task 2.3 stores canonical descriptor identities in a process-local WeakMap so binding never mutates or clones frozen descriptors; conflicting rebinds and explicit-ID mismatches fail with `ZSYS_DESCRIPTOR_IDENTITY_CONFLICT`.
- Task 2.3 uses `unbound.<uuid>` diagnostic identities only until a descriptor is bound. The invocation chain compares unbound descriptors by object identity and canonical descriptors by resolved ID, so aliases can be rejected without making separate unbound objects collide; unbound values are never treated as durable canonical addresses.
- Task 2.3 keeps invocation paths immutable: each child derives a new descriptor-aware `InvocationCallStack`, and the standalone dispatcher carries it in the existing asynchronous scope. Repeated direct or dynamic targets fail before handler execution with `ZSYS_RECURSION_DENIED`; the engine recursion export remains a compatibility barrel until task 2.4 wires generation execution through the shared kernel.
- Task 2.4 keeps the engine-specific invocation pipeline as the generation-aware adapter over the shared kernel: registry lookup, provider/dependency clients, admission, deadlines, cancellation, tracing, hooks, and failure normalization remain in `@zsys/engine`, while the engine now publishes the shared asynchronous dispatcher scope and immutable chain during handler execution.
- The engine dispatcher resolves nested shared targets by canonical descriptor identity against the active `FunctionRegistry`, replacing only the executable handler and retaining target schemas, errors, dependencies, limits, and service-ready metadata. Existing engine options are captured for nested calls so providers, admission, deadlines, cancellation, hooks, parent identity, and outcomes remain unchanged.
- Task 2.4 adds only shared-dispatch wiring and coverage; descriptor methods, observed `calls-function` edges, public `invoke` migration, and services remain deferred to their assigned tasks.
- Task 2.5 attaches `invoke` in `defineFunction` before the existing deep freeze with explicit non-enumerable, non-writable, and non-configurable property descriptors. The closure targets the complete descriptor, so calls remain safe when the method is detached from the descriptor.
- Task 2.5 routes descriptor calls through `@zsys/invocation`'s `dispatchInvocation` seam. The active engine `AsyncLocalStorage` scope therefore performs generation-aware registry resolution and inherited engine execution; outside a scope, the dispatcher creates the isolated standalone kernel. Observed call edges, public dependency migration, compiler cycle removal, tools, and services remain deferred.
- Task 2.6 reuses the existing engine dispatcher and observability hooks: the latest active invocation-chain frame supplies the caller ID, descriptor identity supplies the callee ID, and the resulting `calls-function` edge is advisory telemetry only. Child records continue to use the existing invocation path for distinct IDs and inherited trace/parent correlation; the canonical graph remains untouched.
- Task 2.7 makes descriptor `.invoke` the sole repository function-call authoring path. Function entries are removed from `FunctionDependencies`, `FunctionContext`, public client maps, engine/invocation dependency sources, and generated dependency sources; managed-resource categories remain unchanged and enforced.
- Task 2.7 removes the compiler's declared function dependency edge mapping and static cycle pass. Canonical graph/hash output remains data-only for function calls, while runtime invocation-chain protection and observed `calls-function` telemetry remain authoritative.
- Task 2.7 keeps `FunctionDescriptor.invoke` typed from `InferInput<InputSchema>` so transformed schemas accept caller input while handlers continue receiving parsed schema output.
- Task 2.8 is test-only: it reuses the shared dispatcher and engine registry seams to cover standalone/nested calls, concurrent runtime isolation, inherited trace/deadline/cancellation, boundary validation, provider absence, recursion, dynamic cycles, and cleanup without adding another runtime path.
- The standalone deadline test uses a current wall-clock baseline and a longer child timeout so it verifies inherited parent deadlines without making Effect's real timer expire against a synthetic clock.
- Task 3.1 adds `service` to the shared descriptor kind contract so service references and branded descriptors use the existing ZSys identity/ref validation; graph service nodes and runtime membership remain deferred to task 4.6.
- Task 3.1 keeps `defineService` member facades and service middleware execution out of scope for tasks 3.2–3.3. The services package owns the reusable service/ref types, strict structural guards, normalized reserved-member checks, and a validated deep-freeze helper for the next authoring unit.
- Task 3.2 enforces non-empty service maps in both the generic factory type and runtime, while service IDs remain mandatory until the later inferred-identity task. The factory clones and freezes the map object but retains each original function descriptor by reference.
- Task 3.2 creates direct members by copying descriptor property descriptors and adding a frozen `ServiceRef`, preserving non-enumerable capabilities such as `invoke` without mutating or cloning business handlers. Middleware refs are copied and validated in declaration order; execution and policy ownership remain task 3.3/later runtime scope.
- Task 3.3 keeps service middleware as a non-business callback descriptor: its wrapped handler validates one continuation, waits for downstream completion even when the callback does not await it, freezes copied context patches per invocation, and normalizes declared and policy failures through the shared invocation failure seam.
- Task 3.3 tracks function ownership in a process-local `WeakMap` rather than mutating frozen descriptors. A function may be reused within the same service identity but cannot be registered under another service; existing service facades are checked for their declared owner as well.
- Task 3.3 permits the public declaration scanner's `handler` exception for `ServiceMiddleware` types because this callback is explicitly policy-only and does not own business execution.
- Task 3.4 keeps the function-to-tool contract structurally available from `@zsys/functions` instead of adding a `@zsys/functions` → `@zsys/tools` dependency cycle; `@zsys/tools` already depends on functions. `asTool` copies only the function ref, schemas, and declared errors into the existing handler-free tool view.
- Task 3.4 stores complete safety metadata under optional function `tool` metadata. `asTool(options)` requires complete metadata and uses an explicit `id` when supplied; otherwise it derives `<function-id>.tool`. Zero-argument `asTool()` is typed and runtime-valid only when the function declares complete metadata.
- Task 3.4 copies and validates tool metadata before freezing the function descriptor and installs `asTool` as a non-enumerable, non-writable, non-configurable capability. Tool invocation, approval, timeout execution, and direct runtime behavior remain task 3.5.
- Task 3.5 keeps tool execution in a shared function-owned invoker so `asTool` and `defineTool` gain identical behavior without creating a functions-to-tools dependency cycle. The public target remains handler-free; the closure retains the original function descriptor and dispatches it through the common kernel with source `tool` and the tool timeout.
- Task 3.5 validates the inherited target input before resolving approval, requires an explicit resolver for `on-write`/`always` policies when applicable, denies non-approved decisions, and passes the active invocation scope through unchanged. Public descriptor-cohort expansion remains task 3.6.
- Task 3.6 keeps the expanded evidence in the existing public descriptor/type cohorts, reusing the function-owned tool invoker and service facades rather than adding test-only helpers or new runtime seams. Service runtime materialization remains deferred to tasks 5.1–5.2.
- Task 4.1 keeps identity discovery syntax-only: direct factory calls record binding, factory kind, optional-ID eligibility, and literal option ID presence; export facts retain local/default/named bindings; route operations use named HTTP exports; service facts inspect only inline `functions` maps; and only direct local `const defineError(...)` bindings become error facts. Aliases, indirect maps, and imported module execution remain out of scope.
- Task 4.1 carries the parsed facts through prefilter candidates, source-map entries, extracted descriptors, and normalization so task 4.2 can encode IDs without changing evaluator behavior or performing extra module evaluation. ID encoding, optional factory runtime/type changes, collision handling, and manifest binding remain later tasks.
- Task 4.2 keeps ID encoding pure and syntax-fact-driven: explicit IDs normalize first; named exports use cleaned bindings, default exports retain cleaned file stems, service members combine resolved service/member IDs, declared errors retain their binding spelling, and routes encode safe method/path segments with distinct dynamic and catch-all tokens. Optional factory identity, normalization integration, collisions, runtime wrappers, service graph changes, and manifest binding remain later tasks.
- Task 4.3 reuses `@zsys/invocation`'s `createUnboundIdentity` for omitted IDs across eligible source-scoped factories, resolving only `undefined` so explicit invalid values still go through existing validation; durable app, event, job, bucket, and cache IDs remain unchanged and mandatory.
- Task 4.4 runs source-identity normalization after route-file binding but before local/reference validation, so route method/path facts and rewritten target IDs are available to the existing index without evaluating additional modules.
- Task 4.4 treats a source fact with omitted ID presence, or a source-less `unbound.*` descriptor, as inferred; failed derivation emits a source-located `ZSYS_ID_INFERENCE_AMBIGUOUS` diagnostic with an explicit-ID suggestion. Explicit raw IDs remain untouched until the existing stable-ID validator handles them.
- Task 4.4 reuses the existing source encoders and records `identity: "inferred" | "explicit"` for collision diagnostics. Duplicate inferred/explicit IDs retain the existing `ZSYS_DUPLICATE_ID` code, include the other source location, and suggest an explicit override.
- Task 4.4 rewrites unbound IDs in nested descriptor references, service-member targets, and locally declared error snapshots before reference validation. Service-member functions are indexed only as reference targets; graph nodes, manifest identity wrappers, and runtime binding remain deferred to tasks 4.5–4.7.
- Task 4.4 relies on the existing graph diff contract for move classification: a derived source-path change produces a new logical ID, while an explicit stable ID produces the existing informational source-moved change.
- Task 4.5 emits sorted, deduplicated manifest binding statements before runtime registry materialization. Bindings use the existing WeakMap identity API, cover exported roots plus nested descriptor/error and ref-only function-target paths, and skip generated event-listener roots so one module export is not rebound to both trigger and synthetic-function IDs.
- Task 4.5 keeps frozen descriptors immutable: declared-error constructors, engine targets, and tool runtime lookup/approval/target projection consult the bound identity resolver at use time. The public app package declares the internal invocation package so generated wrapper imports are part of the runtime dependency closure; no graph/manifest contract or public service behavior was added.
- Task 4.6 represents services as data-only graph nodes with source metadata, ordered `members` and `middleware` arrays, and explicit `contains-function`/`uses-service-middleware` edges carrying declaration order. Function calls remain absent from declared canonical edges and are still observed at runtime.
- Task 4.6 keeps `RegistrationPlan.services` optional for compatibility with hand-authored plans while `createRegistrationPlan` always populates it. Service metadata and ordered relationships are projected through the graph hash, compatibility diff, runtime graph snapshot, and inspector-safe graph collections without a graph/manifest contract bump.
- Task 4.7 bumps `GRAPH_VERSION` and `MANIFEST_VERSION` together from 1 to 2. `CONTRACT_VERSION`, `GENERATOR_VERSION`, and `API_VERSION` remain 1 because their envelopes did not change; the built-artifact manifest therefore stays contract v1 while pointing at graph/manifest v2.
- Task 4.7 gives current `ApplicationGraph` and runtime-manifest surfaces literal version types and rejects stale versions independently at CLI build reads, engine registration, runtime Hono materialization, deployment, and supervisor health verification rather than accepting optional legacy version aliases.
- Task 4.7 centralizes service and canonical-identity shape checks in `@zsys/graph` for activation boundaries. The guard rejects durable `unbound.*` identities, including nested declared-error/reference fields, but is not embedded in canonicalization itself so invalid compiler intermediates can still produce their intended diagnostics and non-activatable outputs.
- Task 4.8 reuses the compiler fixture runner for deterministic coverage of every eligible source-scoped kind, nested service members and `InvalidError`, explicit overrides, root/dynamic/required-catch-all routes, and ambiguity and inferred-collision diagnostics. The fixture assertions also cover generated manifest bindings and graph/hash stability across fresh roots and shuffled candidate order.
- Task 4.8 stabilizes only process-local `unbound.<uuid>` placeholders in fixture diagnostics and invalid graph bytes; raw normalization remains available to the harness. This keeps the intentional task 4.3 unbound identity behavior testable without making process-local IDs durable in the graph or manifest goldens.
- Task 5.1 keeps service policy structural and dependency-neutral: `@zsys/invocation` owns the hidden policy marker, service-map lookup, and ordered context-patch runner; `@zsys/services` attaches the marker to frozen member refs, while the engine never imports the services package. Compiled manifests carry live service descriptors, so all source adapters reuse the existing engine invocation seam.
- Task 5.1 deliberately leaves raw-request protection, stronger context isolation/short-circuit semantics, service attribution, request-shape changes, OpenAPI, retries, AI SDK, templates, and documentation to their assigned later units. The function capability uses receiver binding so service facades retain the existing shared `.invoke`/`.asTool` identity expectations while applying the facade policy.
- Task 5.2 keeps request protection at the shared invocation bridge: each policy and handler receives a frozen view over an invocation-local request clone, with plain body values recursively copied/frozen while opaque platform bodies remain on that clone. Service patches are recursively copied/frozen per invocation and middleware layer; opaque non-plain context values remain by reference as the deliberate minimal ceiling.
- Task 5.2 closes the middleware continuation gate when the handler returns, so duplicate or late `next` calls cannot enter the downstream stack; missing, invalid, and declared middleware failures continue through the existing normalized failure path. Service identity is attached to invocation metadata and projected into standalone local logs and engine spans without capturing service-context values.
- Task 5.3 keeps the framework-neutral request separate from reusable input: Hono materializes frozen scalar params or catch-all arrays, repeated query/header values as readonly arrays, and HTTP route/request/trace metadata; the shared isolation bridge clones these collections, while direct, job, event, tool, and agent calls continue to pass `undefined`.
- Task 9.1 keeps the shared HTTP validation result at 422 after the invocation-package extraction unified the source and runtime `InvocationValidationError` class identity; the prior 500 expectation was a stale source/dist mismatch. The inspector redaction fix removes only `middleware` from content-key redaction because it is graph metadata, while request/context/service and related runtime-context keys remain protected.
- Task 9.1 uses the repository-owned tools/agents paths for evidence because a broad `packages/tools` test filter also discovers the vendored Effect checkout and its intentionally unavailable test dependencies. Phase 0 uses the recorded `/private/tmp` temp/cache workaround and a 30-second Bun test timeout for packed export/frozen install child work; no cloud or live model checks are enabled.
- Task 5.4 keeps route inference schema-aware at the top level: matching path names become reusable input, unmatched dynamic/catch-all names are omitted from inferred mappings for request-only access, and any authored request mapping remains a complete override. The existing route-file parser remains the duplicate dynamic-name gate.
- Task 5.5 treats service identity as bounded correlation metadata: graph registration plans, request records, invocation records, logs, spans, query indexes, and inspector filters carry the service ID without capturing service-context content. The existing SSE event envelope is reused, and default redaction omits service/context values while bounded development-redacted capture retains only safe values with nested sensitive fields removed. OpenAPI and later service-facing features remain deferred to task 5.6 and beyond.
- Task 5.6 uses the stable service tag names from service metadata, adds route tags deterministically, and maps route title/description to OpenAPI operation metadata. Runtime docs include the existing service graph nodes so Scalar receives the same grouping document. Generated-client path parameters are added only when route inference left them request-only; mapped reusable input and transport schemas remain unchanged.
- Task 5.7 keeps regression coverage at existing seams: the HTTP integration test composes a real Hono route, service facade, common engine, generated plan, OpenAPI endpoint, Scalar endpoint, and client generator, while the engine tests cover source-order and sibling-call telemetry without adding test-only runtime abstractions.
- Task 6.1 keeps normalized retry classification as the existing `"never" | "later"` strings for compatibility and carries the structured retry-later hint as an optional `afterMs` field. Omitted retry defaults to `"never"`; legacy strings remain valid inputs; structured metadata is validated once at the error boundary and reused by failure normalization and safe envelopes.
- Task 6.1 reuses the existing WeakMap identity binding and constructor lookup for inferred errors. Binding remains non-mutating, while each error created after manifest binding and every normalized safe envelope uses the canonical inferred ID.
- Task 6.2 maps only normalized retry-later failures that carry `afterMs` to `Retry-After: ceil(afterMs / 1000)` in the existing HTTP response mapper. The route handler remains one-shot; omitted retry and legacy retry-later without a delay hint do not emit a header.
- Task 6.3 reuses the existing `applyRetry` path for jobs and durable event deliveries. The normalized application failure's `afterMs` is retained in safe queue metadata and combined with the already-calculated policy delay using `Math.max`; no parallel scheduler or retry loop was added.
- Task 6.3 treats normalized cancellation and timeout/deadline failures, omitted or `never` declared retry, and exhausted attempts as terminal. Existing per-attempt engine deadlines, cancellation propagation, and direct/tool non-retry behavior remain authoritative.
- Task 6.4 keeps regression coverage at the existing job queue, durable event, HTTP response, and descriptor seams. Manual clocks assert exact retry boundaries; direct and tool tests use actual descriptor capabilities and count executions, so no test-only retry path or runtime implementation is needed.
- Task 7.1 pins `ai@7.0.0` with `@ai-sdk/openai@4.0.0` and `@ai-sdk/anthropic@4.0.0` in `@zsys/agents`; runtime usage remains deferred to the later agent units.

Generic normalization preserves EnvRefs, redacts inline secrets, and deep-freezes the result; provider-name/default resolution and registry construction remain task 7.2.
