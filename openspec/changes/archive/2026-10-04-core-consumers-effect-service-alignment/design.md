## Goals / Non-Goals

**Goals:** Make Effect own domain workflows, dependencies, state and resource lifetimes; keep public synchrony and wire/error contracts stable; prove behavior through replaceable Layers, deterministic tests, real transport tests and independent file review.

**Non-Goals:** Introduce public Effect-only client APIs, rewrite the Next Inspector, alter persistence/protocol formats, replace oRPC or native adapters, add speculative caches/resources, upgrade SDKs, perform cloud deployment, or commit/push changes.

## Decisions

### 1. One worktree and four package lanes after a shared foundation

At apply time, create or reuse a suitable managed worktree from the verified current source revision, not the remote default branch. Preserve primary-checkout dirty work and the proposal artifacts; copy only this change's uncommitted planning files if needed. Record the baseline revision and any relevant source overlay. A managed checkout does not include ignored `repos/effect`; read the primary repository's reference by absolute path rather than copying or installing into it.

Phase 1 captures baseline tests, browser entry dependency closure, performance and ownership boundaries. Phase 2 freezes instrumentation contracts, runtime ownership, error translation and test-runner wiring. Then assign disjoint ownership to client, inspector-api, supervisor and testing. With four agent slots, the coordinator can own one lane while three agents own the others. Shared manifests/lockfile, cross-package instrumentation, root scripts, and OpenSpec files have one coordinator owner. No worker edits another lane's files without handoff.

Package implementation can overlap; integration follows client → inspector-api → supervisor → testing. This is the requested review/integration order, not an invented package dependency chain. Each lane uses the frozen baseline contracts. Heavy builds, repository gates, performance comparisons and fixed-port browser runs are serialized. If two lanes need incompatible shared changes or setup/review overhead removes the time saving, serialize them and record why. Four separate worktrees would duplicate setup and require merging uncommitted changes, so one worktree with disjoint file ownership is preferred.

### 2. Cohesive services and explicit compatibility edges

Use existing RELKIT naming conventions with Context.Service contracts, typed Effect methods, Layer.effect acquisition, Service.of implementations and Layer.provide composition. Live and deterministic test Layers implement the same service contract. Acquire shared state, configuration, caches and resources once per owning runtime/scope. Tests and test-only Layers belong under each package's root `tests/<domain>/`; production testing utilities remain production source in `packages/testing/src`.

Use named Effect.fn methods and Effect.gen for domain operations. Pure calculations, predicates, type-only helpers and necessary native callbacks can remain direct. Keep existing Promise, AsyncIterable, synchronous, React and Hono signatures as thin adapters. Execute effects only at those framework/application edges; do not create a runtime per call. A synchronous adapter can run only a synchronously completable workflow. Keep an explicit owner for asynchronous disposal even when a public close method returns synchronously, and prove cleanup through an awaitable owner boundary without changing its public signature.

The official [oRPC Effect guide](https://orpc.dev/docs/integrations/effect) uses an experimental adapter. Do not add it merely to follow examples: retain installed oRPC adapters, wrapping their cancellable calls at the domain edge and translating errors there. Never replace arbitrary Promise rejections/defects with successful fallbacks.

| testing       | Application acquisition; deterministic clock/IDs; fake storage/event/job/realtime providers; scripted models/agent assertions; failure injection | Existing helper exports, payload cloning, snapshot/restore, after-write failure points, test-provider contracts, deterministic time, cleanup on partial acquisition and cancellation, assertions and stable error behavior                             |

Client shared watch/channel identity must retain authorization/tenant/observer/transport distinctions already in its keys. Preserve lazy connection, shared first-snapshot Promise identity, refetch while disconnected, terminal confirmation, duplicate suppression and the existing 100-feed/1,000-lease envelope. EOF must not fabricate terminal job completion. React cleanup owns the observer lease, while accepted server work retains its existing lifetime. Preserve augmentation of DefaultContractRegistry, ClientRegistry, AgentRegistry, ChannelRegistry and JobRegistry. Build-plugin files stay build adapters; schema/type organization must not import runtime services into compiler-only or browser-only entry points.

Inspector's action runtime has a module-level Promise map and a router-local map. The identity is `generationId:action:targetId:idempotencyKey`; its fingerprint includes graph hash, input, invocation/tool-call identities and reason. Move ownership into the appropriate service while retaining conflict detection, concurrent single dispatch, failure behavior and generation isolation. This is an idempotency registry: ordinary TTL/capacity eviction could repeat irreversible actions and is not acceptable without an equivalent validity contract. Native job cursor errors remain fail-fast; unavailable native services remain truthful partial results. Bounded traversal must preserve both policies. Schema projection must preserve selective property access: fixtures deliberately poison forbidden handler/provider getters. SSE heartbeat comments must not advance cursors, and response cancellation must release subscription, heartbeat and pending-pull resources.

Supervisor transitions remain synchronous/atomic at the public boundary where required. Do not insert a yield between reading the expected active generation and switching it. Readiness/hash/fingerprint verification occurs before activation; a failed/obsolete candidate releases its resources without retiring the active generation. Child processes, request bodies, WebSockets, candidate output readers and drain workers need distinct scoped lifetimes. Preserve external process cancellation limits rather than equating fiber interruption with process exit.

Testing's clock bridge currently coexists with wall-clock reads and zero-delay polling in fake jobs. Route domain time through the injected clock, coordinate event availability explicitly, and preserve any documented manual-time behavior. Hanging model turns and pending approvals need cancellation-aware ownership. Application/provider/service acquisition must release successful earlier acquisitions if a later step fails. A fake cache with set/delete/increment, per-write TTL, and snapshots remains a storage model; a memoization Cache is not a replacement for that contract.

### 4. Capability selection and pinned-source evidence

Review all 25 `use-effect` families together. Record applicability by domain in normal phase review notes; avoid a separate per-symbol catalog or adding APIs solely for coverage.

- **Service, Schema, Tagged Errors, Error Management, Data:** services own decisions and workflows; decode actual unknown wire/storage inputs using schema authorities already present. Derive companion types, preserve optional fields/defaults/unknown-field rules, and use tagged internal state where it clarifies transitions. Internal Schema.TaggedError values translate to existing public errors/statuses. Keep defects, interruption and mixed causes distinct.
- **Observability, metrics, tracing, logs, Platform Logger:** instrument independently callable domain operations with bounded labels, outcomes, monotonic timing and workload metrics. Use existing application sinks and redaction. Emit meaningful enabled-level logs; verify real configured thresholds and output. Provision loggers/exporters at runtime edges, with fiber-local child overrides and no global mutation. Telemetry failures must not change application results.
- **Fibers, PubSub, Queue, Stream, concurrency:** own workers/listeners with scoped fibers; supervise failures and join cleanup. Finite effectful work uses ordered/bounded traversal with the existing per-item failure policy. Streams keep their scope alive through consumption, early exit and pending-pull cancellation. Specify capacity and overflow for callbacks/broadcast; do not add buffers to pure lists. Layer acquisition must finish.
- **Clocks, scheduling, Scope, AcquireRelease:** use injected time, monotonic durations, bounded idempotent retry schedules and deterministic synchronization. Pair native listeners, handles/processes and acquired services with exactly-once release, including partial-acquisition failure. Keep masks narrow and pass AbortSignal where supported.
- **RcMap, caching, Refs:** RcMap is a strong candidate for client shared job/realtime resource leases. Build it once per owner, scope each borrower, and preserve key equality, final-borrower shutdown, replacement and idle retention. Specify capacity failure translation if a capacity is introduced; do not add a new public limit incidentally. Cache fits repeated derived lookups only with correct success/failure TTL, invalidation, generation/security keys and capacity. Refs own in-memory atomic transitions; SynchronizedRef applies only to short effectful critical sections. Authoritative idempotency and fake writable storage retain their own semantics.
- **Testing, traits, Configs:** use @effect/vitest and it.effect with TestClock/Deferred/Queue/Latch and fake Layers. Preserve real-host tests where native behavior is the assertion. Read runtime configuration during acquisition with explicit option/provider precedence. Adopt equality/hash/order traits only where keys or domain values need them; no generic Trait module exists.

Verified rc.115 `node_modules/effect/src/RcMap.ts` uses scoped leases and increments borrower counts before awaiting acquisition; its release closes only after the last borrow, with optional idle retention. Invalidation removes the mapping while keeping a borrowed entry alive until release. Its source includes executable examples; dedicated core vendor tests are absent. Retained `repos/effect/packages/effect/test/http/HttpRouter.test.ts` demonstrates Layer composition and acquire/use/release; the corresponding HTTP source illustrates service/lifecycle integration. Installed source is authoritative for exact exports/signatures. Each lane must inspect implementation/delegates plus available examples/tests for every additional selected pattern before editing, and cover absent upstream tests with focused local regressions. Do not copy obsolete lowercase Config examples or old Effect export paths from reference material.

Testing imports the Drizzle service adapter, so load the Drizzle integration reference for service activation/disposal changes; do not introduce row-query changes where none exist. Client uses oRPC, so its integration reference applies. Other integrations are loaded only if the owning code actually uses them.

### 5. Shared instrumentation without a browser dependency leak

Inspect the existing invocation and execution instrumentation before selecting a common home. Prefer a browser-safe owning leaf/export already within the permitted dependency graph; server adapters can supply their existing sinks. If a small shared extraction is necessary, the coordinator owns it and its compatibility tests. Do not import `@relkit/runtime-effect`, native logger/filesystem/process modules, or server-only barrels into client browser entry points. Check both source imports and built dependency closure.

Each operation records once; compatibility wrappers do not record it again. Trace stream consumption through completion, rather than only iterator construction. Avoid recursively emitting query/live-feed diagnostics back into the same Inspector feed without a suppression boundary. Keep IDs in safe contextual traces/logs when allowed, never unbounded metric labels. Test standalone calls under default/configured logging and isolated registries, inherited/overridden child levels, redaction, success/failure/defect/interruption and sink failure.

### 6. Organization and independent review at every phase end

## Risks / Trade-offs

- Browser bundle/server dependency growth → inspect built entry closure and measured bundle deltas before client acceptance.
- Cache eviction repeating controls or resource release ending another observer → keep authoritative deduplication semantics and prove RcMap lease/isolation behavior.
- Async conversion breaking atomic activation or public synchrony → preserve synchronous transitions and test stale candidates/concurrent switches.
- Scope closed before an iterator/body is consumed → transfer ownership through consumer lifetime and test pending pull/return/throw/abort.
- Native Promise/process work outliving interrupted fibers → pass real cancellation and join capable owners; document unavoidable native settlement before fixture removal.
- Extra telemetry creates feedback, overhead or secrets → runtime-owned sinks, bounded context, actual-output tests and isolated performance comparisons.
- Existing tests omitted during runner migration → reconcile old/new test paths and counts, root discovery, fixtures and direct command references.
- Sparse vendor or stale guide signatures → inspect installed rc.115 source and local regressions, recording unavailable vendor tests honestly.
- Demo uses stale builds or mutates shared evidence → resolve every package from the worktree and run isolated copies with new evidence paths.
