# Decisions

- The predecessor archive/spec changes are treated as part of this change because they implement completed tasks 1.1–1.5.
- The `apps/inspector/next-env.d.ts` edit is treated as a generated validation side effect, not separate authored work; retain it visibly until a worker verifies or cleans it.
- No Linear lifecycle hook applies because this repository has no `openspec/linear.yaml`.
- Optional Wayfinder alignment does not apply because the change has no named Wayfinder decision source.
- Task 2.1 uses `packages/provider` for `@relkit/provider` and `packages/local-service` for `@relkit/local-service`; this remains distinct from the later `integrations/packages/local` `@relkit/local` implementation.
- Both protocol packages began as value-free dependency-free shells; task 3.x added provider behavior and task 4.3 added local-service contract versions with type-only dependencies on canonical JSON and provider recipe references.
- The root scope allowlist, release descriptions, project references, and lockfile were updated because the repository’s existing checks enumerate every `packages/*` workspace; no integration implementation or SDK dependency was added.
- Task 2.2 registers the catalog at `integrations/catalog`; standalone integration directories remain task 2.3, so no integration behavior or SDK dependency is introduced yet.
- The existing generic `turbo.json` build/check/typecheck tasks already apply to every registered workspace, so no redundant integration-specific Turbo aliases or filters were added.
- `workspacePackageDirectories` is the shared, Node-compatible source of publishable workspace discovery for packed smoke, release classification, metadata checks, and action changelog paths.
- The integration-root scope exemption only permits alternate-IaC vendor names/content inside registered integration roots; the normal boundary scan still covers those files.
- Continue the remaining change in the current Codex task. The obsolete orchestration skill, its three supporting profiles, guide requirement, and release-check dirty-worktree exception are removed.
- Production mode rejects every normalized `local-only` provider binding during the shared compiler provider pass. The diagnostic names the canonical binding and leaves development-mode Docker reconciliation unchanged.
- Task 2.3 integration shells expose only `.` and declare no dependencies. Runtime, local-recipe, host, infrastructure, access, and deployment-engine subpaths and dependencies are introduced only by their owning later tasks.
- Dependency direction is enforced from workspace paths and manifests rather than a second package-name allowlist. Standalone integrations may depend on the four cross-cutting protocols (`@relkit/provider`, `@relkit/local-service`, `@relkit/observability`, and `@relkit/deploy`) plus only the capability and canonical-data contracts their runtime implements. Redis therefore depends on `@relkit/cache` and `@relkit/contracts`; application and engine dependencies remain forbidden, and external SDK dependencies remain integration-owned.
- Integration roots are the authoring exports. Redis and S3 additionally expose `runtime` and `local-recipe`; Docker, local, Cloudflare, AI SDK, Sentry, and OTLP expose `runtime`; AWS exposes `host` and `infrastructure`; Pulumi exposes `engine`. AWS access is deferred to its implementation task.
- Packed export verification is manifest-driven after comparison with the central release export contract, avoiding a second hardcoded resolver list.
- Existing Konsistent package wildcard paths remain present verbatim and gain integration path alternatives; the catalog is a separate semantic cohort with explicit rules. No existing convention was weakened to eliminate its advisory findings.
- The provider-ownership removal and replacement package cohort is a minor pre-1.0 release. Changesets' existing fixed group intentionally advances all 49 publishable packages together to 0.2.0; no compatibility or migration layer is added.
- Synthetic-secret scanning uses the same publishable workspace discovery as release packing, preventing nested integration artifacts from bypassing the release security gate.
- Provider protocol brands are type-only unique-symbol brands over explicit string discriminators, so descriptors remain nominal in TypeScript without introducing symbol keys into their JSON representation. Builders detach input through the canonical serializer before freezing it.
- Named binding values use `binding-value-ref` descriptors owned by `@relkit/provider`; `@relkit/config` adds overloads to the existing `env` helpers and depends one-way on the provider protocol. Application `env-ref` values remain separate and cannot be passed through `defineEnv` as binding fields.
- Adapter descriptors carry at most one default local-recipe reference. The shared source normalizer derives connected versus local-only behavior from required connection fields; wrappers cannot wrap wrappers, which makes duplicate release/local source composition unrepresentable through the public builders and rejected at runtime when forged.
- Connection contracts classify authored values as fixed or fallback. Local/infrastructure outputs are authoritative; fixed authored declarations conflict, fallback declarations yield, and binding-value lookup remains explicit input rather than reading or mutating application environment state.
- Provider profile normalization is independent of logical descriptor kinds: it accepts one capability plus direct/map input, while selection receives the logical descriptor ID and optional descriptor/default choices. This keeps one precedence implementation for cache, bucket, job, event, model, and observability consumers.
- Normalized binding access comes only from explicit source/binding metadata. Adapter behavior is projected intact and never inspected for policy-shaped keys, preventing integration-specific option extraction in core code.
- `defineApp` stores normalized provider profile maps on the same singular top-level capability keys used for authoring. Explicit defaults are preserved but singleton defaults are not synthesized because shared profile selection already owns sole-profile inference.
- The public break removes every legacy authoring/runtime-integration forward immediately. The old topology validator and three structural runtime types stay as explicit engine-only exports only until the planned graph/registry refactor, avoiding a throwaway duplicate legacy protocol while exposing no old constructor.
- Public type fixtures use low-level protocol builders only until standalone integration constructors land in task 4; they assert the canonical `defineApp` shape and removed surface without inventing temporary app-level adapters.
- Public JSDoc treats `defineApp`, `env`, binding-value references, adapters, and source wrappers as the authoring primitives; normalization and resolution exports remain protocol implementation seams rather than duplicating user-facing examples on every helper.
- Documentation generation is not weakened to accept removed APIs. Its stale `defineConfig` catalog entry is migrated with the complete executable guide cohort in task 10.
- Redis URLs are secret-bearing connection fields and the public constructor accepts only named secret binding references; resolved runtime strings enter only the selected binding. `connectionTimeoutMs` remains adapter behavior, while `atomicIncrement` is explicit feature metadata.
- Runtime role exports must be importable for static verification under Node without loading a Bun runtime implementation. Redis therefore resolves `Bun.RedisClient` only when a client is constructed, while descriptor evaluation and module inspection remain I/O-free.
- S3 flattens credential references into declared connection fields so local/infrastructure outputs can satisfy or override only the connection contract. `forcePathStyle` and `signedUrlTtlSeconds` remain behavior; signed read/write URLs remain explicit adapter features.
- Portable bucket keys are validated once in `@relkit/buckets` rather than independently by each integration. S3 user-metadata names use HTTP's lowercase canonical form so behavior remains portable across compatible object stores.
- `docker()` delegates to the shared local-source builder, so one implementation owns purity, freezing, local-only/overlay normalization, missing-recipe validation, and nested-wrapper rejection. `@relkit/local-service` owns transport-neutral plan/state types, `@relkit/local` exposes them, and `@relkit/docker/runtime` exposes only static materializer identity until task 7 adds engine I/O.
- Cloudflare KV uses the official bearer-authenticated REST value API and declares its 60-second minimum TTL as behavior; R2 uses its S3-compatible `auto` region and direct Web Crypto SigV4 implementation so `@relkit/cloudflare` has no AWS SDK or cross-integration dependency.
- One `aiSdk()` descriptor represents one model profile and keeps vendor/default-model behavior separate from resolved connection values. OpenAI and Anthropic SDK dependencies and lazy construction now live only in `@relkit/ai-sdk`; `@relkit/agents` retains the generic selector/execution contract and no vendor registry.
- Sentry receives only already-safe messages and tags through its standalone runtime and delegates buffering, flush, and close to its own SDK. Generated CLI servers contain no Sentry import, initialization, capture branch, optional dependency, or global flush hook.
- OTLP uses the platform fetch API for its standalone OTLP/HTTP JSON transport instead of adding an SDK. Bounded queuing, batching, retries, counters, and fan-out belong to the canonical telemetry pipeline in task 8.6 rather than this transport ownership move.
- Sentry and OTLP authoring roots remain empty until task 8.1 replaces the legacy observability provider with the typed exporter map; temporary authoring configuration would create a second contract to delete.
- Deployment integration metadata uses one generic versioned role contract in `@relkit/deploy`. AWS role subpaths and the Pulumi engine subpath expose frozen structural identities and depend on no package except that protocol.
- AWS authoring remains empty until task 9.5 implements `aws(adapter, options)`. The legacy plan-v2 cloud/Pulumi packages are not forwarded through the standalone packages; tasks 5 and 9 replace their contract, loader, and materializers directly.
- The optional catalog has no root mega-barrel. Each public subpath directly re-exports one standalone authoring root, preserving exact value/type identity and preventing a single import from evaluating unrelated integrations or runtime/SDK subpaths.
- Minimal-install verification reuses release tarballs. Each standalone package is loaded from its own dependency closure before the aggregate fixture is assembled; a sibling integration in that closure is an error, and successful Node imports prove public entries do not statically require another integration's SDK.
- Runtime-integration plan v1 is a canonical JSON contract in `@relkit/contracts`; provider override state v1 is owned by `@relkit/local-service` beside local plan/state. Provider protocol v1 remains in `@relkit/provider`, avoiding duplicate version authorities.
- Version constants advance before shape/golden migration so every subsequent compiler task emits only the new cohort. Previous graph/OpenAPI fixtures remain visibly stale until task 5.10 rather than being mechanically renumbered while they still encode the old topology.
- Graph nodes retain `source` for canonical source locations, so normalized provider release-source data is named `providerSource`. Non-sensitive fixed connection literals remain available for runtime wiring, while binding references are projected only as named metadata and sensitive literals/defaults are omitted.
- Infrastructure and access roles are projected beside their source/access metadata so deployment and Inspector consumers can distinguish role provenance without inferring ownership. Application engine and host selections use the same version-1 role projection.
- The singular application `model` key and an agent's `model` selector share a property name only at different descriptor kinds; compiler selector normalization is therefore agent-only. Agent selector prefixes select physical model profiles, replacing the removed environment model registry.
- Manifest v8 references one fixed runtime-integration artifact by version, canonical filename, and graph hash. The filename is framework-owned rather than author-supplied; the engine validates the reference before handler registration, while plan-byte hashing joins the activation fingerprint in task 5.8.
- Integration package manifests own `relkit.integration` ID/export metadata, and the optional catalog owns an explicit subpath-to-standalone-package map. Resolution follows only imports already present in application source, records the installed package version, verifies the selected export remains inside that package, and never scans for or imports executable integrations during compilation.
- Runtime-integration entries are selected from graph requirement edges and deduplicated by their complete registration/provenance tuple. Multiple required profiles using the same adapter therefore load one registration, while configured but unused bindings produce no plan entry.
- Local-service plans retain every declaration and carry sorted `requiredBy` graph relationships; development can reconcile required entries while explicit local lifecycle commands can operate on all declarations from the same plan. Current recipes have no public service-level options, so their safe plan configuration is `{}` and fixed image/health defaults remain package-owned rather than duplicated from adapter behavior.
- Deployment plan v3 removes the ownership/provider-binding list now: application engine and host, connected runtime wiring, infrastructure lifecycle, and access are distinct integration-role records. Existing neutral application/job/event/bucket/cache materialization sections remain until task 9 replaces the AWS-oriented consumer, but they no longer determine provider ownership or synthesize connected-resource lifecycle.
- Package-owned runtime metadata names exact capability, adapter, and protocol registrations beside one exports-map key. The compiler validates that static metadata without importing executable modules; runtime-reported metadata remains a separate startup check in task 6.2.
- `runtime-integrations.ts` is a compiler-owned generated artifact derived only from the verified plan. Imports are deduplicated by package/version/export and stable-sorted, while registration uniqueness is enforced independently by `(capability, adapter)` so two integrations cannot claim the same runtime slot.
- The activation fingerprint hashes generated source bytes, not runtime object shape: graph identity is already canonical, manifest source is hashed before it imports the separate fingerprint JSON, and runtime/local plan sources include their deterministic trailing newline. This avoids a manifest/fingerprint hash cycle.
- Build-time manifest rebasing creates a distinct production cohort, so production recomputes and persists its fingerprint after rebasing. The bundled server statically imports plan JSON and verifies it against the embedded expected fingerprint before readiness; `readBuilt` independently verifies on-disk source bytes before start.
- Supervisor and Inspector generation identity use the complete fingerprint as the activation unit. A matching graph hash alone cannot admit a candidate whose manifest, integration plan, local plan, or override generation differs.
- Version admission is enforced by each artifact owner and again at activation seams. Regeneration guidance follows ownership: compiler artifacts use `relkit check`, production cohorts use `relkit build`, deployment plans use `relkit deploy preview`, and local state uses `relkit local up`.
- Deployment-plan admission occurs before any Pulumi resource constructor runs; an old plan cannot partially mutate infrastructure before rejection.
- Compiler fixtures resolve integration metadata through the production resolver and discover every workspace package through the shared workspace helper. Test-only integration metadata and hardcoded package symlink lists are not maintained.
- The broad valid fixture now exercises integrations that exist in the current standalone cohort. Its legacy SQS/EventBridge declarations were removed rather than preserved through private constructors; dedicated job/event compiler tests retain contract coverage until explicit integrations land in later gates.
- Generated servers consume the compiler-emitted runtime integration module directly. Build does not reconstruct, rescan, or dynamically discover package imports, and core no longer imports the Cloud/AWS factory barrel.
- Runtime modules expose one conventional `runtimeIntegration` metadata value. The compiler-generated wrapper owns package/version/export provenance, while the loaded namespace reports integration and registration identities; every planned registration must match, and a selected package may report additional valid registrations from the same runtime export.
- Runtime connection resolution reuses the provider protocol's single precedence implementation. The engine only reconstructs named references from validated graph metadata and selects local/infrastructure maps by full binding ID; pipeline values remain a separate explicit input from resolved application environment values.
- Executable runtime registrations extend the verified static registration identity with one `create(context)` function owned by the selected integration package. Core maps registrations by integration/capability/adapter/protocol, never imports concrete providers, and exposes only graph-singular capability keys.
- Provider lifecycle diagnostics identify the binding and lifecycle phase but deliberately omit third-party exception text, because SDK readiness/construction errors may contain resolved credentials or endpoints. Partial generations are still released in reverse order.
- Environment names continue to govern only handler environment validation and unrelated runtime behavior; they are absent from provider registry inputs. The legacy app topology validators and local fallback factory were deleted once the graph/integration registry no longer consumed them.
- Test provider replacement is an exact `capability -> profile -> value` map. A fake's optional `provider` is the runtime client and optional `close` is its registry-owned release hook; no default fake is synthesized for a missing profile.
- Core job materialization owns only structural queue/scheduler contracts and generic retry transitions. Concrete queues and schedulers are injected; a schedule-bearing plan fails before provider work when no scheduler is supplied, while a plan with no schedules needs no implementation.
- Provider requirements are admitted from logical consumer nodes, not trusted from edges alone. Capability and profile must match the consumer projection exactly; unused provider nodes remain outside construction and configuration resolution.
- Model readiness is profile-local, and event contract registration is profile-local. No aggregate model registry or cross-profile event contract broadcast is retained.
- Duplicate required capability/profile bindings are invalid runtime metadata because the public registry key is exactly that pair. Multiple logical consumers may still share the same binding ID and generation.
- Local planning remains compiler-owned and pure. Docker discovery and materialization consume its emitted protocol later; no second runtime planner or compile-time Docker probe is introduced.
- Docker execution uses direct argv spawning with no shell. Docker allocates host ports through loopback-only publish syntax; inspected responses establish the selected port. Label filters are stable-sorted, all returned resource identifiers are validated before command reuse, and safe errors omit Docker stderr and argv values.
- Adapter packages export one conventional `localRecipe` value through their declared local-recipe subpath. The cross-cutting protocol describes only the container inputs and post-health output resolver; project labels, names, ports, secrets, and lifecycle remain materializer/orchestrator inputs. Redis pins its multi-architecture image digest and uses append-only persistence so ordinary container replacement can reuse the named data volume.
- MinIO generated-secret declarations map names to container environment keys; actual values are orchestrator-owned and will be supplied through a protected environment file, never Docker argv or labels. The recipe uses its own S3 signer to create its isolated bucket after protocol health succeeds. Path-style addressing is the adapter default because the same immutable adapter behavior must work for local MinIO and release S3 sources; callers can explicitly disable it.
- Local project identity is `sha256(canonical real project root, NUL, stable application ID)`. Docker labels use one reverse-domain key set and carry a versioned recipe identity; every label operation recomputes structural project identity before it can query or mutate resources.
- Project leases are ordinary versioned JSON guarded by a short atomic directory lock. Detached leases intentionally have no PID and are adoptable; an attached handle that adopted detached ownership restores that lease on release. Attached liveness uses PID signal-zero checks, with injectable checks retained only for deterministic tests.
- Local state has no caller-selected paths: lease and override filenames are fixed beneath `.relkit/state/local/<local-project-hash>`. Existing symlinks are rejected before reads, writes, locks, or removal. Override generation uses a random UUID rather than hashing credentials, so activation identity cannot become an offline secret oracle.
- Development owns one lazy local-service reconciler for the full `DevSession`. Each candidate receives only its activation-bound override-file path after required services are healthy; generated runtime code validates state identity before constructing providers, and shutdown closes local ownership only after candidate draining.
- Local CLI commands are thin operations over the development reconciler and fixed project lease/state boundary. Detached startup is the only non-blocking persistent mode; stop preserves volumes, reset requires confirmation, and every destructive Docker query is constrained by the canonical project labels before resource IDs are reused.
- Telemetry policy is normalized by `@relkit/observability`, while Sentry and OTLP own only their pure exporter descriptors and runtime exports. Telemetry plan entries use the existing static integration contract but bypass provider construction because exporters are consumed by the independent fan-out pipeline rather than capability/profile bindings.
- External trace sampling hashes the canonical trace ID into one stable rate decision instead of retaining an unbounded trace-state map. Logs, diagnostics, and generation records bypass trace sampling; local persistence and live publication complete before the decision is consulted.
- External logs default to `info` and use one ordered severity table. Records carrying an error outcome/identity and all diagnostics bypass trace sampling, while successful trace-correlated records inherit the stable trace decision.
- Telemetry runtime modules expose one conventional `createTelemetryExporter(context)` beside existing integration metadata. The canonical fan-out resolves only named binding references from explicit runtime values, schedules each lane independently, and retains per-exporter health/counters without dynamic discovery.
- Sentry owns SDK buffering directly and has no RelKit queue or per-Sentry sampling option. OTLP owns the one RelKit bounded queue, coalesces adjacent trace units where possible, retries deterministically, and aborts active transport work at its shutdown deadline.
- Exporter errors are reduced to one safe local diagnostic code/message plus configured exporter name. The collector admits these required diagnostics even when ordinary diagnostic capture is disabled, and the persistence call explicitly skips external dispatch to prevent recursion.
- CloudWatch is host infrastructure, not an application provider or telemetry exporter. Production emits redacted canonical JSON to stdout, and the AWS ECS host alone owns the log group and `awslogs` routing; local development keeps the human sink.
- Inspector API v1 adds topology and runtime metadata without adding a compatibility version or exposing generic graph configuration. Provider/exporter projections name identities, profiles, features, package versions, local phases, sampling, and counters only; resolved values, package export paths, and integration configuration are discarded at the API boundary.
- Inspector views consume only those bounded API projections and reuse the existing accessible UI system. Package provenance is joined from the graph response, while runtime lifecycle/exporter state comes from the additive runtime endpoint; no client-side integration discovery, raw configuration renderer, or second state layer is introduced.
- Deployment v3 admission is exact at the new role/operation boundary: connected bindings carry runtime wiring only, infrastructure operations own lifecycle, and access must target an infrastructure binding. Diff deletion is destructive only for lifecycle-owning resources; removing connected wiring never implies deletion of the external resource.
- Template redaction policy sets the required development retention ceiling explicitly to 64 KiB; the schema does not infer an unbounded or hidden default.
- Template tests replace every configured model profile explicitly, so packed smoke never activates a real vendor SDK or depends on ambient credentials.
- Authoring validation discovers registered standalone integration package roots and permits their declarative imports while retaining the framework-import prohibition and normal boundary scan.
