## ADDED Requirements

### Requirement: Compiler operations are lazy and composable

The compiler SHALL expose composable operations whose construction does not perform source access, validation, mutation, process acquisition, or publication. Each execution SHALL allocate its own compilation-owned mutable state. Native dependencies SHALL be replaceable by caller-supplied implementations at the operations that use them. Synchronous and Promise compatibility APIs SHALL preserve supported return values, ordered diagnostics, thrown or rejected errors, canonical bytes, hashes, and activation decisions.

#### Scenario: A compilation is constructed and executed twice

- **WHEN** a caller constructs a compilation operation without executing it and later executes that same operation twice
- **THEN** construction performs no compiler work and the executions produce equivalent results using separate mutable indexes and diagnostics

#### Scenario: Native dependencies are replaced

- **WHEN** a caller supplies deterministic package or source readers to an operation that requires those readers
- **THEN** the operation uses those implementations without performing hidden native reads for that dependency

#### Scenario: A compatibility adapter is used

- **WHEN** the same supported input is evaluated through a composable operation and its existing synchronous or Promise adapter
- **THEN** successful results and generated bytes agree and the adapter retains its documented legacy failure shape after owned cleanup finishes

### Requirement: Compiler boundary rejection is distinguishable from defects

The compiler SHALL validate untrusted package metadata and persisted or evaluator records before treating them as domain records. Independently callable validation operations SHALL expose expected rejection through a typed failure channel and SHALL preserve unexpected defects and interruption. The normalization orchestration boundary SHALL retain its established pass-exception diagnostic conversion and ordered continuation policy while propagating observer defects and interruption.

#### Scenario: Parsed package JSON has an invalid root shape

- **WHEN** a package manifest contains valid JSON whose root is null, an array, or a primitive
- **THEN** the package metadata boundary rejects it with a contextual typed failure before domain code reads record properties

#### Scenario: A validation operation runs independently

- **WHEN** a caller runs route, integration package, runtime plan, or artifact validation with unsupported metadata
- **THEN** the operation exposes the expected validation rejection through its typed failure channel without requiring an enclosing workflow to reinterpret a defect

#### Scenario: An injected reader contains a programming defect

- **WHEN** a dependency implementation produces an unexpected defect outside the documented normalization recovery boundary
- **THEN** the original defect remains observable rather than becoming a validation diagnostic or an unavailable record

#### Scenario: A normalization pass encounters a recoverable exception

- **WHEN** an existing recoverable pass exception occurs during ordered normalization
- **THEN** normalization records the existing stable failure diagnostic, continues the documented later passes, and suppresses activatable outputs

#### Scenario: Normalization is interrupted or its observer throws

- **WHEN** the compilation fiber is interrupted or a pass observer throws an unexpected exception
- **THEN** cancellation or the original observer defect propagates without being converted into a recoverable pass diagnostic

### Requirement: Compiler native resources have explicit execution ownership

Compiler operations SHALL own acquired evaluator children, output readers, detector hooks, and temporary artifact handles for their documented execution lifetime. Success, expected failure, defects, and interruption SHALL finalize acquired resources before the operation settles. Cancellation SHALL reach supported native reads; each atomic publication SHALL finish its owned publication and cleanup before interruption completes, without deleting a temporary file it did not acquire.

#### Scenario: Evaluator work is interrupted

- **WHEN** cancellation occurs while evaluator input or output is pending
- **THEN** the owned readers are cancelled and the child is terminated and reaped before the operation settles

#### Scenario: Detector acquisition fails partway through

- **WHEN** a native hook fails to install after earlier hooks have been installed
- **THEN** every acquired hook is restored and cleanup failures remain observable after the remaining restoration attempts

#### Scenario: An atomic artifact write is interrupted

- **WHEN** cancellation arrives after the operation has exclusively acquired its temporary file
- **THEN** owned publication and cleanup finish before interruption completes and no acquired temporary file is stranded

#### Scenario: Exclusive temporary file acquisition fails

- **WHEN** another writer owns the proposed temporary path
- **THEN** the failed operation reports the acquisition failure and leaves that writer's file intact
