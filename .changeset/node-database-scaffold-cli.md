`relkit add database` now writes a service that runs on Node as well as Bun: it opens the database
with `openSqliteDatabase`, `openPostgresDatabase` or `openMysqlDatabase` from `@relkit/drizzle`
instead of importing `bun:sqlite` or `drizzle-orm/bun-sql`, and adds `pg` (PostgreSQL) or `mysql2`
(MySQL) to the dependencies. The `db:generate` script is `drizzle-kit generate` instead of
`bun --bun drizzle-kit generate`, the generated `drizzle.config.ts` reads `.env.local` and `.env`
when drizzle-kit runs on Node, and the next steps name the project's package manager
(`npm run db:generate`). A service generated by an earlier release keeps working on Bun; to run it
on Node, replace its `drizzle(...)` call with the matching function and install `pg` or `mysql2`.

The agent skill that every new project carries (`data-apis.md`) shows the same clients and the
`npm run` and `bun run` forms of the database commands instead of `bun:sqlite` and `bun run`.
