A realtime subscription whose identity scope or session epoch does not match the session now answers `409` with `IDENTITY_PRECONDITION_FAILED` before any stream is opened; it used to open the stream and fail inside it, which a client saw as `500`. Channel authorization is unchanged: a channel the caller cannot read still ends the stream with the concealed `NOT_FOUND`.

`createWriteUrl(key, { contentType, contentLength })` now takes the upload's content type and length, both optional; calls without them are unchanged. A declared type outside the bucket's `allowedContentTypes`, or a length above `maxObjectBytes`, fails with the bucket policy error (`RELKIT_BUCKET_POLICY_INVALID`) before a URL is signed, and the provider binds the type and the exact length into the URL so storage rejects any other upload. Without a declaration the URL binds neither and the bucket's limits are not enforced on that upload. The new `BucketPolicyError` (exported from `relkit/buckets`) is the policy error of every provider; the local provider's `LocalBucketPolicyError` now extends it. A bucket client given a `policy` applies it to `put` and `createWriteUrl` before calling the provider. The bucket clients a running application builds (in function contexts and on the application handle) now receive the bucket's declared `maxObjectBytes` and `allowedContentTypes`, from the authored `defineBucket` descriptor or, for a bare reference and in a generated server, from the bucket's node in the application graph (bound to its source with the new `bindBucketPolicy` from `relkit/engine`), so the limits hold with `@relkit/s3` and every other provider, not only the local one.
