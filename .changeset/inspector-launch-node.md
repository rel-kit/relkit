The Inspector now starts from either runtime. `npm run inspector` (the launcher on Node) used to stop at once with "verify launch options, private connection directory and persistent history mount", and `bun --bun run inspector` printed "Ready" and then answered 500 on every page because its interface ran on Bun. The interface and the history worker now run on a real Node.js: the running one when the launcher runs on Node, otherwise the first `node` on `PATH` that is not Bun's alias; the alias directories are removed from the children's `PATH`. When no Node.js of the supported release (>=20.9.0) is found, the Inspector stops with `ui.node-missing` or `ui.node-unsupported` and says what to install; a failed start of the interface names the Node.js executable it tried.

The terminal now says when no `relkit dev` session is found for the project and how to start one, logs one line on every connect and disconnect with the session id, and names the candidates and `--connection-file` when several sessions are running; none of these lines repeats on every discovery poll. Every new subscriber of the Inspector's live stream receives the current application session state as its newest `generation.changed` event, and the status endpoint `/_relkit/v1/storage` reports the Inspector's session with the application under `application` (`state`, `sessionId`, `generationId`, `sessions`, `since`), apart from the interface's own stream.

`/_relkit/v1/storage` now names its loss counters apart: `recordsLostBeforeHistory.byApplicationProducer` (records the application's producer could not hand to its inspection buffer) and `recordsLostBeforeHistory.byInspectionBuffer` (records that buffer evicted before the Inspector stored them) are real loss before history, while `missedLiveUpdates` counts live invalidations the Inspector's stream dropped for a slow interface and loses no record. `dropped` and `producerDropped` stay for compatibility and are deprecated.
