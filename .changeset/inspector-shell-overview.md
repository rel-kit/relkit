Fixed: the Inspector says when the application is away. The header shows three states apart: the page's stream to the Inspector, the Inspector's session with the application, and history. When the development server stops, every page says so within a second or two, with since when, that retained history is still shown and how to start `relkit dev`; with no session it says it is waiting for one, and with several it names them and `--connection-file`. Pages that act on the running application say they are unavailable instead of showing blank content, and request and log lists say live updates are paused. A tab opens one event stream instead of two or three, so several tabs stay connected, and an idle page no longer reads history every three seconds. The overview counts every retained request and 5xx answer instead of the newest 100, names records lost before history apart from missed live updates, hides export counters when no exporter is configured, and labels generation history as session starts, reloads, restarts and failed reloads grouped by `relkit dev` run. The theme follows the system until you choose one, an unknown address shows "Page not found" without a hydration error, graph cards stay readable at the first fit, the zoom control follows the dark theme, and every time shows its zone. The Inspector's status answer now reports `lastSessionId` and `lastConnectedUntil` (the last session of this run and when it stopped answering), so a tab opened after the application stopped says "stopped answering" instead of "Waiting for a development session".
